# Phase 3.5 IPC architecture re-derivation

Document status: CURRENT
Evidence scope: architecture was re-derived from origin/main `7c8ed152fb3ed5fa1c996f6b447396ad6aa0caca`; implementation and QEMU evidence are current through this source set. The accepted execution/synchronization choices are E1/A and are recorded in ADR-0025.
Current reference: [Current scheduler contract](../kernel/scheduler.md)

## Review basis and decision boundary

After the architecture review, the user instructed continuation through the complete Phase 3.5 implementation, tests, documentation and PR. Implementation proceeds with execution option E1 and synchronization option A. ADR-0025 records the selected invariants; this review remains the comparison record and does not itself close #26.

The retained implementation includes the bounded endpoint/request arbiter, initialized copied frames, scoped grants, transactional receive/collect, wake/ack mailboxes and continuous idle/resume. The original technical receipt records 124 checks per DEV/PROD profile and 46 exact-event IPC mutation runs. After integration with main ac63c75, both positive profiles again pass all 124 checks; the integration receipt separates current observations from unchanged historical enforcement evidence. The 144-group performance baseline per profile is retained. Bounded acceptance is complete; the separate acceptance review retains the current-source mutation and EN/RU correspondence evidence.

The fetched and periodically refreshed `origin/main` and the work branch start at `7c8ed152fb3ed5fa1c996f6b447396ad6aa0caca`. The original checkout remains untouched and its unrelated local documentation changes are excluded. GitHub issue [#26](https://github.com/lifeFedorovAlexey/KOLVRT/issues/26) tracks this bounded acceptance; [#75](https://github.com/lifeFedorovAlexey/KOLVRT/pull/75) and [#76](https://github.com/lifeFedorovAlexey/KOLVRT/pull/76) are merged. [#27](https://github.com/lifeFedorovAlexey/KOLVRT/issues/27) and [#28](https://github.com/lifeFedorovAlexey/KOLVRT/issues/28) remain later service gates.

The review’s execution-architecture decision is resolved: IPC adds a continuous owner-local idle/resume path while retaining whole-session retirement. A continuously admitted idle owner is not declared quiescent merely because no process is READY. The kernel keeps fixed affinity, exclusive scheduler access and immutable mappings; independent CPU sessions, migration and per-process retirement remain outside this milestone.

Execution option E1 with synchronization option A preserves fixed affinity, exclusive scheduler access, immutable mappings and the conservative retirement barrier. It adds an explicit continuous execution mode and split syscall continuation, recorded in ADR-0025. Existing dispatch/step fixtures remain separately scoped. Independent admission, per-process retirement, migration and supervisor policy are excluded.

## Synchronization alternatives

These alternatives concern endpoint/request storage. None authorizes foreign mutation of scheduler storage, a global IPC lock, a universal KernelObject or IRQ acquisition of an ordinary lock.

| Dimension                       | A: split syscall and endpoint-local synchronization                                                                                                                                                                           | B: bounded atomic endpoint structure                                                                                                                                                                              | C: endpoint owner and per-CPU mailboxes                                                                                                                    |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Safety                          | Snapshot/retain under scheduler ownership, release scope, synchronize endpoint, release guard, reacquire exact executing context. Receive/collect use explicit reservations across copy-out; no guard spans scheduler access. | Multiword payload ownership must be reserved separately from terminal CAS. Publication and reclamation need a complete per-entry proof; one atomic flag must not conceal an ordinary lock inside scheduler scope. | Only endpoint owner mutates queue/arbiter. Remote admissions and responses need generation-safe copied mailbox ownership and acknowledged teardown.        |
| Ownership                       | Private namespace stays owner-local. Endpoint references and reservations retain storage independently of user mappings.                                                                                                      | Each slot has explicit reservation, publication, delivery, terminal and retired ownership states.                                                                                                                 | Mailbox record owns copied work until owner accepts/rejects; acceptance and retained result are distinct records.                                          |
| IRQ behavior                    | IRQ publishes bounded work/wake records only. Endpoint synchronization happens in a deferred syscall/native continuation with no scheduler borrow. Existing ordinary Lock cannot simply be used from trap.                    | IRQ may publish bounded atomics, but retries/scans must have explicit finite bounds and deferred continuation.                                                                                                    | IRQ acknowledges and flags mailbox work; owner drains bounded records outside IRQ.                                                                         |
| Progress and starvation         | A nonblocking, syscall-specific endpoint permit requires a documented BUSY path for admission and reliable deferred terminal work. No spin while the owner is suspended and no lost deadline/cancel record.                   | CAS contention can starve a caller; lock-free does not establish bounded per-call latency. Define rejection and retry budgets before claiming progress.                                                           | Owner CPU service availability is an explicit dependency. Fair bounded mailbox draining is required; exhausted control capacity cannot drop terminal work. |
| Cross-CPU wake                  | Publish exact wait identity to the target CPU; owner alone changes BLOCKED to READY.                                                                                                                                          | Same owner-local wake protocol; atomics do not authorize remote task mutation.                                                                                                                                    | Wake records share the mailbox machinery, with distinct ownership/control capacity.                                                                        |
| Performance                     | Extra short phases and object synchronization; measure copy/reservation/wake costs.                                                                                                                                           | Potentially less guard handoff; more atomic metadata and retries. No speed claim without samples.                                                                                                                 | Adds remote admission round trips and mailbox copies; batching may help later.                                                                             |
| Complexity                      | Lowest conceptual queue/arbiter complexity, but split copy transaction and deferred lock protocol are substantive new work.                                                                                                   | Highest publication, ordering, generation and reclamation proof burden.                                                                                                                                           | More protocol states, control-capacity reservations, acknowledgements and owner-failure cleanup.                                                           |
| Future services/drivers         | Concrete ownership and commit boundaries extend without kernel service policy. DMA/effect contracts still need separate proofs.                                                                                               | Storage algorithm can evolve without altering transport outcomes; weak-memory validation grows with topology.                                                                                                     | Owner locality may scale, but driver locality and backpressure must be separately measured.                                                                |
| Unsafe surface                  | Existing Lock UnsafeCell invariants cannot be assumed for a new syscall permit. Any necessary private storage wrapper needs explicit lifetime/access proof and negative controls.                                             | Atomic-byte payload storage can avoid new unsafe; speed is not grounds for unchecked access.                                                                                                                      | Safe owned records are possible; any shared non-atomic mailbox storage needs an audited publication wrapper.                                               |
| Compatibility and reversibility | Preserve handle encoding/rights. Replace private synchronization without changing accepted request outcomes.                                                                                                                  | Same observable contract; algorithm can later replace A after equivalent evidence.                                                                                                                                | Preserve transport contract; changing endpoint owner requires explicit acknowledged handoff, not identity rebinding.                                       |

Recommendation: A with endpoint-local, nonblocking deferred synchronization, never the current ordinary Lock acquired directly in trap. The syscall pipeline must pass owned values across scopes. Copy-in/copy-out remain synchronous inside exact current-task Access scopes. A request or terminal response reservation, not a borrowed Task or user pointer, survives the intervening object phase.

## Execution architecture decision

All three choices require actual timer/SGI wake handling when no task is runnable. Merely adding an atomic queue inside the current callback does not implement this. Synchronization alternative B can be combined with E1 or E2; it does not resolve execution lifetime by itself.

| Dimension          | E1: continuous owner-local IPC execution, whole-session retirement                                                                                                                                    | E2: independent CPU sessions and per-process retirement                                                                                                                                | E3: coordinator-owned event-driven step pump                                                                                                                                 |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Correctness        | Each owner retains its admitted namespace/context while idle. No READY task means native idle with timer/mailbox recheck, not Done. Both CPU acknowledgements and unlink still precede frame release. | Each process needs retained scheduler/root leases and owner-local detachment acknowledgement independent of peer execution. Rewrite whole-session detached/namespace-return semantics. | Both CPUs detach after each bounded step; coordinator owns contexts/namespaces while sleeping for events. A mailbox must wake the coordinator, not mutate a completed Local. |
| Security           | Preserve exact generation, fixed affinity, current-copy proof, no-lock storage scopes and global retirement safety. Idle cannot publish fake completion.                                              | New lookup, admission and reclaim races affect address-space lifetime, ASID reuse and handle owner movement. Require a new retained-root proof under ADR-0017/0018/0021.               | Preserve conservative retirement safety; single coordinator controls admission. Deferred records must distinguish active versus detached namespace ownership.                |
| Performance        | Avoid a whole two-CPU handoff per IPC wait/wake; barrier remains for session completion. Reclamation waits for session quiescence.                                                                    | Removes global retirement coupling and allows admission while peers execute; increased synchronization/lease overhead needs measurement.                                               | Per-step rendezvous and namespace handoff remain on the execution path. Both peer preemption and IPC latency depend on coordinator wake/drain scheduling.                    |
| Complexity         | Add native idle/resume, next-deadline scheduling and generation-safe owner mailbox; retain existing retirement protocol.                                                                              | Largest lifecycle change: safe retained roots, per-process acknowledgements, independent namespace ownership and concurrent registry operations.                                       | New coordinator idle/timer protocol, targeted owner restart and wake records spanning dispatch generations. Simpler reclamation, more round-boundary wake cases.             |
| Future scalability | Later per-process retirement may improve scalability without changing IPC identity/outcomes. Supervisor policy remains #27.                                                                           | Stronger foundation for concurrent admission/reclamation, but expands Phase 3.5 substantially.                                                                                         | Coordinator remains a bottleneck and may require replacing the execution pump for independently persistent services.                                                         |
| Compatibility      | Keep synchronous dispatch/step fixtures and their historical scopes; add a distinct continuous IPC path. New execution contract requires an ADR, but does not weaken storage exclusion or freeze ABI. | Supersede the conservative retirement portion of ADR-0017 and related current-copy/namespace assumptions explicitly.                                                                   | Keep step semantics; generalize coordinator signals and add true event-driven sleeping. Do not claim current bootstrap polling is production idle.                           |
| Reversibility      | Private execution mode can later use independent retirement after equivalent quiescence evidence.                                                                                                     | Hardest rollback once lifecycle callers depend on concurrent admission and independent completion.                                                                                     | Private pump can be replaced if IPC correctness stays invariant; all mailbox reservations must first drain.                                                                  |

Recommendation: E1 for Phase 3.5. Its accepted change should be limited to continuous execution/idle and split syscall continuation. Do not relax the whole-session frame retirement barrier, admit migration, or add supervisor/restart policy. E2 requires a separate retained-lifecycle architecture decision. E3 is a viable conservative alternative, but must implement actual event-driven sleeping and own explicit wake handoffs at session boundaries.

The original execution decision gate is resolved by the accepted E1/A choice in ADR-0025; the alternatives above remain the design comparison record.

## Proposed transport contract after the decision

Endpoint is a separate concrete primitive. Its immutable identity/generation, exact bound service generation, fixed-affinity CPU, owner/domain charges, capacity, admission state and retained references are not user-selected authority. A caller-local SEND grant admits requests. Receiver authority is an explicit nondelegable bootstrap-installed endpoint binding in the service namespace plus exact service-generation validation; PID equality alone is insufficient. A delivered request token permits only commit/reply for its exact endpoint/request/service generations. No RECEIVE/REPLY rights are proposed without a separate demonstrated authority distinction.

The recommended candidate replacement is a separately versioned experimental transport contract, retaining LE64 handles with the actual 8/56 encoding. native.request/0 stays an identified superseded host proposal until its lifecycle/consumer record and host fixtures are updated together. No external production consumer has been established by this review; absence in the host fixture is not proof that no consumer exists anywhere. Reject unsupported versions explicitly and keep ABI-FREEZE absent.

Endpoint lifecycle: Vacant → Bound → Live → Closing → Retiring → Vacant with a strictly greater generation. Slot exhaustion quarantines storage. Admission closes before shutdown terminalization. Handle close/revoke stops future lookup/admission without cancelling accepted requests or delegated references.

Request lifecycle: reserved unpublished storage → QUEUED → DELIVERED → optional COMMITTED → one terminal result → successful collection or explicit cleanup → retired. Every accepted request owns initialized bounded payload/response storage, immutable snapshot length, endpoint reference, consumer domain request charge, service queue/active charges, deadline and exact service-token generation. Failed admission rolls back all ownership without publishing an ID or waiter.

| Event winning the arbiter          | QUEUED or DELIVERED before commit            | COMMITTED                                                    | Already terminal                                         |
| ---------------------------------- | -------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------- |
| Valid service reply                | COMPLETED with initialized response          | COMPLETED with initialized response                          | Reject stale/duplicate reply; retain original result     |
| Consumer cancellation              | CANCELLED_BEFORE_EFFECT                      | EFFECT_UNKNOWN; never claim rollback                         | Explicit already-terminal result; no second wake/release |
| Absolute deadline                  | EXPIRED_BEFORE_EFFECT                        | EFFECT_UNKNOWN                                               | Preserve original result                                 |
| Service death or endpoint shutdown | CANCELLED_BEFORE_EFFECT with truthful reason | EFFECT_UNKNOWN unless completion already won                 | Preserve original result                                 |
| Consumer death                     | Cancel before effect and abandon delivery    | Retain ownership until terminal resolution; no user delivery | Release abandoned receipt exactly once                   |

The no-effect guarantee is the transport's authorized commitment boundary. It does not establish durability or roll back arbitrary external actions. Future device/storage/network services must couple their own irreversible-effect boundary to this contract; the kernel does not inspect application semantics or enforce service discovery/restart policy.

Receive/collect are transactional: reserve an exact queued/result generation, copy fully to the executing service/client under current Access, then commit dequeue/consumption. Failure retains the queued request/result unless a concurrent independent cancellation/death legitimately terminalizes it. A token copied just before cancellation must subsequently be rejected by the arbiter. A copy error cannot manufacture a successful delivery or consume the client ID.

Wait identity includes exact ProcessId, endpoint/request generation, wait sequence and kind. Check condition → publish registration → recheck → publish BLOCKED only if false. Producers publish condition/result before wake record. The target owner alone matches the record and changes BLOCKED to READY; stale/duplicate records cannot create another running owner. One active blocking reason per process and one authorized endpoint receive waiter are explicit bounds. Idle entry must recheck pending records after registration and before sleeping.

Use Release publication and Acquire observation for queue/result bytes and mailbox records; synchronize arbiter transitions and reservations with explicit AcqRel CAS or the reviewed endpoint permit. Retiring endpoint/token generations require acquired final ownership release plus absence of queued, delivered, terminal, waiter and mailbox references. A timeout is never a teardown acknowledgement. Deadlines are absolute boot-local counter ticks with checked conversions, distinct from CPU-slice budgets. The nearest deadline must stay armed while the owning CPU is idle; IRQ publishes bounded deferred expiry, and the deferred path uses the same terminal arbiter.

Initial payload bound is 256 bytes, with capacity-1 and capacity-4 endpoint configurations. Queue order is successful admission linearization, not wall-clock CPU ordering. Request budgets charge consumer outstanding work and service queued/active work separately; release moments follow actual ownership. Endpoint pool storage needs an explicit quota dimension or an explicitly bounded/bootstrap-owned reserve; do not silently use an unrelated quota. The safe baseline has four payload copies: client → kernel request → service, then service → kernel response → client.

## Reuse, replacement and acceptance obligations

Reuse only generation-safe process/handle/domain identities, current Access/Snapshot, attenuated SEND/TRANSFER/REVOKE rules, retained domain Charges, fixed-affinity running-owner checks, precise copy fault recovery and owner-local ASID retirement. Keep Event as a coalescing notification primitive. Its retained-pool approach is evidence for bounded lifetime, not an endpoint queue or automatic IPC-wakeup implementation.

Replace the security.rs single-cell Work/Receipt model for general IPC with dedicated endpoint/request storage, service receive, transactional collect and one terminal arbiter. Keep native.notification/1 only if its existing bounded independent contract remains useful; removal or refactoring must preserve truthful historical evidence and current feature status. No code was removed or refactored by this review.

The implementation covers payload, authority, queues, waits, SMP, cancellation/deadline, death, accounting and reclamation with real EL0 fixtures. Final acceptance is audited against the original task; physical ARM remains UNKNOWN and is not inferred from QEMU. New IPC storage adds the reviewed Cell Sync and HRTB unsafe access wrapper; separate unsafe ranges describe immutable linked EL0 images and execution contexts. The inventory is not a safety proof.

The bounded IPC mechanism is BOUNDED_IMPLEMENTED and READY for Phase 3.5; native.request/1 remains EXPERIMENTAL and unfrozen. The [acceptance review](ipc-phase35-acceptance-review.md) records the current-source 46 mutations and semantic EN/RU correspondence. #27 is the supervisor gate; #28 is the persistent-service gate.
