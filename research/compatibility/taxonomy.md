A documented Linux mechanism is evidence, not a KOLVRT support requirement. Review original constraints, counterexamples, accepted native contracts and a named consumer before confirming debt. ## Family inventory and counterexamples

The initial observation vocabulary includes allocation, locking, IRQ, deferred work/timers, DMA, PCI, USB, firmware, power management, device model, sysfs, ioctl, network and block. Investigate lifecycle/refcounting, storage, sound, DRM/KMS/GPU, synchronization, cache coherence/IOMMU and firmware/Device Tree/ACPI separately; omitted interfaces are unknown coverage, not absent requirements. One broad family can require several distinct state/authority contracts.

For each family, the next dossier must state original problem/first-known history/later layers, observable semantics, source-backed users, hardware versus Linux-specific obligations, accepted or proposed native difference, reusable coverage, security/performance/maintenance cost, migration and removal. Classification allows BUG/DESIGN_FLAW and reasonable HISTORICAL_CONSTRAINT/HARDWARE_REQUIREMENT/COMPATIBILITY_REQUIREMENT/PERFORMANCE_TRADEOFF/ACCIDENTAL_SEMANTICS/SECURITY_WORKAROUND/OTHER; evidence chooses it.

DMA is a counterexample to assuming that Linux lacks explicit ownership. PREEMPT_RT is a counterexample to treating every spinlock as identical execution-state manipulation. Workqueue redesign is evidence of a corrected resource/concurrency trade-off, not evidence to rebuild worker pools in native EL1. Device documentation must be cross-checked against actual source rather than copied as a permanent object specification.
