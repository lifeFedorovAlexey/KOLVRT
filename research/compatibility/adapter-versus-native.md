## Sequential decision gates

| Gate                     | Required review evidence                                                                                                                   | Consequence of a gap or violation                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Workload                 | Named consumer, exact useful operations, hardware/ARM64 relevance and acceptable outcomes                                                  | Missing consumer: DEFER; no invented coverage or benefit                            |
| Semantic closure         | Pinned revision/configuration, direct/transitive helpers, macros, callbacks, shared state, transport, firmware and feature negotiation     | Unknown closure: DEFER; incompatible unbounded closure: STOP COMPAT                 |
| Native authorization     | Per-caller effects, grant/delegation/revocation scope, budgets and narrow native enforcement                                               | Expanded rights or Linux semantics required in EL1: REJECT adapter                  |
| Lifetime and containment | Stop admission, accepted-request attribution, callback/IRQ/DMA quiescence, reset, restart/rebind generation and truthful terminal outcomes | Unverified guarantee: DEFER; proposed timeout-as-retirement or blind replay: REJECT |
| Alternatives             | Compare bounded adapter, native rewrite, deferral and unsupported under equivalent guarantees                                              | Choose a disposition per case; popularity or API counts cannot decide               |
| Ownership and exit       | Named maintainer, review window, update/churn plan, migration target, removal dependencies and falsifiers                                  | No owner or executable exit plan: DEFER supported status                            |
| Cost and testability     | Workload-selected resource limits, measured-or-unknown costs and reproducible negative/rollback tests                                      | UNKNOWN remains UNKNOWN; speed cannot override failed security gates                |

REJECT means the stated adapter proposal violates a gate; it does not mean the hardware can never be supported. DEFER means missing evidence/contract prevents admission. UNSUPPORTED is an explicit product scope decision after reviewing a real need and feasible alternatives; absence of evidence alone is not that decision. A native rewrite is also subject to hardware isolation, lifetime and authority gates.

## Selecting budgets without a universal score

The eventual consumer owner and native-contract reviewer must predeclare the useful workload, concurrency, device features and operation outcomes. Set memory/request/queue/state limits from allowed grants and failure capacity; set latency/throughput/tail limits from that workload's requirements. Record rationale, measurements, compiler/configuration, raw receipts and loss scope before accepting a comparison. Planning effort estimates require a decomposed dependency/migration/test/maintenance work list and estimator; both estimates are UNKNOWN here. No arbitrary driver-count threshold or weighted security score is assigned.

Compare equivalent authority, buffers, queue depth, cancellation/reset and useful results for adapter and native paths. Include IPC, exclusive CPU, copies, memory, tail behavior, dependency churn, support and removal costs. Reuse [benchmark policy](../../docs/architecture/benchmarking.md); a fast adapter is admissible only after its guarantees pass. If a measured route is faster, retain that result. Hardware DMA/cache/ordering requirements persist for both alternatives and are not automatically COST-L debt.

## Case A: VirtIO block, narrow boot-target research

**Observed Linux mechanisms.** [Request construction, lines 140–158](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/block/virtio_blk.c#L140-L158) uses scatterlists and a virtqueue with GFP_ATOMIC. [Configuration work, lines 948–960](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/block/virtio_blk.c#L948-L960) defers configuration processing. [Removal/freeze, lines 1564–1607](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/block/virtio_blk.c#L1564-L1607) drains work, resets the device and deletes queues; freeze also freezes the block queue. These are distinct synchronization obligations, not interchangeable API stubs.

**Proposed scope, not an executed configuration.** Investigate one QEMU virt ARM64 transport, fixed negotiated features and bounded read/write/flush requests for a named future block consumer. Transport, backend persistence, queue ownership and protection remain unestablished. Exclude zoned operations, discard/write-zeroes and optional power-management behavior only if the negotiated feature/configuration contract rejects them truthfully; the source still contains these paths. No Linux build, physical hardware relevance or full helper closure is claimed.

**Historical justification.** Reusing Linux blk-mq, scatterlists, feature negotiation and deferred work reasonably lets a driver compose with existing block infrastructure and asynchronously changing devices. That is an inference from the reviewed current source, not proof of the original author's motive or origin date. GFP_ATOMIC suggests an allocation-context edge to CANDIDATE COST-L-0001; accepted native behavior and complete recurrence evidence are still missing. Do not infer sysfs/ioctl debt or a confirmed incompatibility from the driver name.

## Case B: USB mass storage, existing subsystem semantics

**Observed Linux mechanisms.** [Resource acquisition, lines 855–883](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/usb/storage/usb.c#L855-L883) allocates a URB, invokes device-specific initialization and starts a control thread. [Disconnect/resource release, lines 887–973](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/usb/storage/usb.c#L887-L973) stops scanning/admission, removes the SCSI host, wakes/stops the thread and releases coherent buffers/references. [Quirk processing, lines 675–725](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/usb/storage/usb.c#L675-L725) handles protocol/transport overrides and device flags. Bulk-only scope cannot silently claim support for every USB storage transport or quirk.

**Proposed scope, not a device claim.** Consider a future identified bulk-only device and a specific read-only consumer after a native USB transport contract exists. Exclude UAS, other protocols, arbitrary SCSI commands, unknown quirks and writable persistence unless separately reviewed. Native USB host-controller DMA/IRQ/reset and device-disconnect semantics are dependencies even when this one file has few direct DMA symbols. No real device was selected or inventoried.

**Historical justification.** An existing USB/SCSI infrastructure, control thread and quirk catalogue reasonably preserve asynchronous command/disconnect behavior and nonconforming hardware. Rewriting those rules without evidence can lose required behavior. This is a design-rationale inference from current code; exact historical origin and applicability of each quirk remain UNKNOWN. Linux's [DMA guide](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/Documentation/core-api/dma-api-howto.rst) already specifies mapping lifetime and barriers: calling all DMA implicit-lifetime legacy is a disconfirmed premise.

## Rejection, sensitivity and falsifiers

Reject a proposal that ports either complete Linux driver by stubbing helpers, grants an arbitrary command capability, treats a timeout as proof of queue/DMA retirement or replays an uncertain write after restart. The reviewed sources explicitly depend on stop/drain/reset ordering; deleting that obligation to reduce shim size is not a bounded adapter. Under the existing native boundary, needing Linux reclamation/USB/SCSI policy in EL1 is STOP COMPAT, not permission to grow the kernel.

For VirtIO block, an established native transport and a fixed consumer may change DEFER into a reviewable native design. A mandatory Linux-specific external contract or demonstrated reuse with a complete bounded closure could favor an adapter instead. New required zoned/PM/transport features invalidate the subset comparison. For USB storage, a proven necessary device quirk may favor bounded reuse; a standard verified device and native USB service may favor rewrite. An unisolatable required controller, unknown reset effects or absent retirement evidence keeps both alternatives deferred or motivates an explicit unsupported decision. Source-reference reach alone changes neither disposition.

Future negative-test specifications: revoke a caller during admission; disconnect with accepted requests; delay a callback past restart; fail reset; retain a DMA mapping; send an excluded feature/command; substitute another consumer's buffer; corrupt a completion; lose provenance/coverage. Require no unauthorized effect, no premature reuse, generation-safe rejection and truthful failure/unknown outcome. They are not executed results; host/schema tests cannot establish device quiescence.
