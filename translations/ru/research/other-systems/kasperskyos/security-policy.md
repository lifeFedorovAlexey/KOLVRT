# Выдача capabilities и динамическая политика

## Сведения источника

CE сочетает права handles с решениями модуля безопасности и контекстами отдельных ресурсов. Провайдеры участвуют в авторизации именованных пользовательских ресурсов. [Управление доступом](https://support.kaspersky.com/help/KCE/1.2/en-US/overview_resource_acces_control.htm). Руководство CE 1.2 описывает PSL-правила, отказ по умолчанию при отсутствии правила, модели состояния и построение тестов политики. [Руководство, печатные страницы 246–249](https://support.kaspersky.com/help/KCE/1.2/en-US/KasperskyOS-CE-en-US.pdf#page=246).

Это опровергает простое противопоставление «политики KasperskyOS» и «capabilities KOLVRT»: описанная модель сочетает оба механизма. Статически собранная политика может принимать решения по текущему состоянию. Старый Education Kit также описывает политики состояния/времени; не считать названия его семейств API CE. [Историческая модель политики, 2020](https://support.kaspersky.com/kos/educationkitbeta0.1/en-us/security_policies.htm).

## Предлагаемое сочетание для KOLVRT

Разделять native-выдачу и использование: выдача выбирает объект, ограниченные права, caller и семантику отзыва; каждый admission проверяет handle и текущие условия, необходимые для корректности. Стабильные grants могут исключить повторную оценку несвязанных глобальных правил, но это гипотеза оптимизации, а не измеренное преимущество или освобождение от проверок.

| Условие                       | Необходимая текущая проверка или явная семантика аренды                               |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| Время/временное делегирование | Проверять срок в монотонной эпохе; не использовать истёкшие grants                    |
| Квоты                         | Атомарно учитывать до публикации; удерживать расходы до окончательного освобождения   |
| Отзыв/смена credentials       | Задать линеаризацию и семантику принятой работы; проверять текущее поколение/контекст |
| Переназначение устройства     | Завершить DMA/IRQ; отменить старое поколение до нового владельца                      |
| Сетевая политика              | Закреплять допустимый peer/flow; учитывать изменения согласно контракту               |
| Полномочия нескольких сторон  | Удерживать аутентифицированные вклады и задавать срок согласия                        |

## Отказы и условие принятия

Кешированное «разрешено» с последующим отзывом credentials — гонка проверки/использования. Допустимый endpoint службы не означает разрешение любого её внутреннего ресурса. Новые типы проходят issue #7; глобальная координация не требует EL1 сама по себе. Измерить аренды с выдачей, адресные динамические проверки и центральную политику на одинаковых нагрузках перед выбором. Сейчас отвергнуть универсальный policy DSL; использовать небольшую явную таблицу решений, пока нагрузка не докажет её недостаточность.
