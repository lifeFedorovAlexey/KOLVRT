# Домены безопасности

## Сведения источника

FAQ разработчика Kaspersky описывает изолированные компоненты, явно разрешённые взаимодействия и цели/допущения TCB конкретного решения. Маркетинговые формулировки не являются независимым доказательством локализации. [Официальный FAQ](https://os.kaspersky.com/faq-general/).

## Предлагаемая граница KOLVRT

Определять домен через действительную защиту адресного пространства, native-права, допустимую область ресурсов/эффектов и контракт отказа. Crate, API family и семантический домен состояния не обязательно являются доменами защиты. Экземпляры служб и общие адресные пространства должны быть видны: компрометация одного совместно размещённого компонента может затронуть остальные.

Идентификатор вызывающего должен поступать из доверенного контекста входа/транспорта, а не из поля сообщения consumer. Служба может использовать собственное право на хранилище для разрешённой операции caller. Проверять область эффектов caller и сохранять атрибуцию во вложенных запросах. Служба входит в TCB любого свойства, которое обеспечивает только она; EL0 не снимает это обязательство.

## Ревью и тесты

Admission связывает поколение домена, права, квоты и закреплённый семантический маршрут. Авторизация по текущему состоянию требует синхронизации с admission, а не устаревшего кешированного решения. CPU-изоляция не ограничивает враждебный DMA без отдельной аппаратной границы. Моделировать подделку идентификатора, междоменный импорт handle, отказ службы, исчерпание квот и повторное использование привилегий после перезапуска. Реальные проверки ошибок памяти требуют EL0, которого сейчас нет. Стоимость создания/наблюдения и масштабирование общего назначения требуют будущих измерений.
