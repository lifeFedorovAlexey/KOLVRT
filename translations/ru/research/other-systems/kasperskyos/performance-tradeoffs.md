# Компромиссы производительности

## Свидетельства

Сопоставимые latency, throughput, стоимость CPU и размер TCB исследованных систем локально не измерялись. Опубликованные числа с разных машин/конфигураций не ранжируют эти проекты. seL4 описывает быстрый IPC с явными условиями применения. [IPC fastpath](https://docs.sel4.systems/Tutorials/ipc.html). Исходная статья Capsicum показывает постепенное ограничение объектных полномочий в UNIX без обязательного полного перехода к микроядру. [Watson и соавторы, USENIX Security 2010](https://www.cl.cam.ac.uk/research/security/capsicum/papers/2010usenix-security-capsicum-website.pdf).

## Предлагаемый протокол эксперимента

Использовать одинаковые операции, гарантии безопасности, исходы отказов, распределения payload, квоты и конкурентность. Закреплять исходники, компилятор, платформу, число CPU, accelerator/оборудование, единицы таймера и прогрев. Сохранять сырые samples, отказы, p50/p95/p99, throughput, работу CPU, copies/bytes, память и число переходов; писать «неизвестно» при отсутствии данных. Время QEMU TCG — наблюдения эмулятора, а не утверждения аппаратной latency.

| Вариант                              | Исследуемый контрпример или стоимость                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| Выдача прав с локальной проверкой    | Изменение credentials/отзыв могут отменить раннее решение                                   |
| Адресная проверка текущего состояния | Admission синхронизирует смену предиката; учитывать contention                              |
| Центральная оценка политики          | Дополнительный dispatch/обход состояния могут иметь цену; кеш не сохраняет устаревшие права |
| IPC с копированием                   | Ограниченные copies и снимки; сначала сравнить малые payload                                |
| Shared-memory аренда                 | Цена mapping/pinning/cleanup, мутации, DMA и доказательств порядка                          |
| Batching/асинхронный ring            | Амортизация переходов против latency, fairness, квот и отмены                               |

## Следствие для размещения

Оптимизация не отменяет инвариант эффективных полномочий и доказательство допуска в EL1. Оценивать применимые альтернативы; нет требования сначала реализовать каждый ring/zero-copy. Отвергнуть дорогой IPC benchmark как единственное основание переноса службы в EL1. Текущая SMP-работа не даёт сравнения одинаковых нагрузок будущих служб. Прототипы начинаются только после отдельной авторизации предпосылок scheduler/EL0/authority.
