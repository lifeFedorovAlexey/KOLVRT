# Шаблон исследования механизма Linux

Факты, гипотезы исторической причинности, инженерные сравнения и принятые решения KOLVRT различаются. Не называйте объяснение модели фактом разработчика. Недостающие доказательства — UNKNOWN. Используйте versioned docs.kernel.org, pinned source, Git history, LKML/subsystem discussions и документацию сопровождающих. Фиксируйте version, commit/tag, architecture/configuration при необходимости, path/locator и review date. Внешний механизм не является требованием KOLVRT.

Домены растут по необходимости: process, scheduler, memory, locking, rcu, irq, workqueue, device, pci, usb, dma, iommu, vfs, block, network, power, firmware, security, abi. Стабильные адреса имеют вид `linux.<domain>.<mechanism>`.
