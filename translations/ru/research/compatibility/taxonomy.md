## Метод и граница доказательств

Проверено 2026-10-03 относительно Linux v6.12 commit adc218676eef25575469234709c2d87185ca223a. Единица анализа — повторяющееся несовместимое semantic assumption, а не название API или количество драйверов. Документированный механизм Linux является evidence, а не требованием поддержки KOLVRT. Перед подтверждением debt проверить исходные constraints, counterexamples, принятые native contracts и named consumer. Primary documentation поддерживает наблюдения ниже; точное introduction и causal history остаются открытыми, пока не установлены отдельно.

[Реестр](../../docs/architecture/compatibility-debt.md) выделяет три стабильные CANDIDATE identities. Ни у одной нет implemented adapter, подтверждённого named KOLVRT consumer, support window или measurement. Эти записи — исследованные гипотезы, а не confirmed incompatibilities. Другие seeds остаются явными research questions или hardware requirements; квота записей не заполняется.

Русские поговорки сопровождают три записи, отражают конкретные failure modes и ничего не утверждают о людях или сообществах.

## Family inventory и counterexamples

Начальный observation vocabulary включает allocation, locking, IRQ, deferred work/timers, DMA, PCI, USB, firmware, power management, device model, sysfs, ioctl, network и block. Отдельно исследовать lifecycle/refcounting, storage, sound, DRM/KMS/GPU, synchronization, cache coherence/IOMMU и firmware/Device Tree/ACPI; пропущенные interfaces — неизвестное coverage, а не отсутствующие requirements. Одна широкая family может требовать нескольких различных state/authority contracts.

Для каждой family следующий dossier должен указать original problem/first-known history/later layers, observable semantics, source-backed users, hardware и Linux-specific obligations, принятое или proposed native difference, reusable coverage, security/performance/maintenance cost, migration и removal. Classification допускает BUG/DESIGN_FLAW и разумные HISTORICAL_CONSTRAINT/HARDWARE_REQUIREMENT/COMPATIBILITY_REQUIREMENT/PERFORMANCE_TRADEOFF/ACCIDENTAL_SEMANTICS/SECURITY_WORKAROUND/OTHER; выбор определяется evidence.

DMA — counterexample предположению, что у Linux нет explicit ownership. PREEMPT_RT — counterexample одинаковой execution-state manipulation всех spinlocks. Переработка workqueue свидетельствует об исправленном resource/concurrency trade-off, а не о необходимости worker pools в native EL1. Device documentation проверяется по actual source, а не копируется как постоянная object specification.
