# Адаптер или native-драйвер: критерии решений и разобранные случаи

Document status: CURRENT
Evidence scope: исследовательские решения по исходникам для issue #57; без принятого контракта драйвера, реализации или результатов выполнения.
Current reference: [Зафиксированный корпус](linux-driver-api-map.md)

## Свидетельства и граница решения

Проверено 2026-10-03 относительно main KOLVRT 2b190e2caa8665da5918d1a52e2d278cf8bf519b и коммита Linux v6.12 adc218676eef25575469234709c2d87185ca223a. Работа расширяет [начальный обзор API](taxonomy.md) и [отчёт об охвате адаптеров](high-leverage-adapters.md), отвечает на [#57](https://github.com/lifeFedorovAlexey/KOLVRT/issues/57) и передаёт выводы в [#59](https://github.com/lifeFedorovAlexey/KOLVRT/issues/59). Два намеренно различающихся случая хранения используют прежний удобный корпус; это не представительная выборка драйверов. Исследование исходников выполнено; предложенные ниже тесты драйверов не запускались.

Принятое [решение о платформе](../../../../docs/architecture-decisions/0005-platform.md) задаёт ARM64/VirtIO как направление, но оставляет DMA isolation открытым. [Размещение](../../../../docs/architecture-decisions/0008-placement.md) допускает первый echo slice и откладывает общее размещение устройств. [Правила полномочий](../../../../docs/architecture-decisions/0013-security-boundaries.md) запрещают выдачу недостающих прав совместимостью и требуют отдельного обоснования privileged necessity. Ни исходник Linux, ни адресное пространство EL0 не предоставляют native-контракты USB/block/DMA. Исследовательские решения ниже не одобряют Linux Driver Host или новую capability.

## Последовательные условия принятия решения

| Условие                   | Требуемые свидетельства для review                                                                                                              | Последствие пробела или нарушения                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Workload                  | Названный потребитель, точные полезные операции, применимость к оборудованию/ARM64 и допустимые исходы                                          | Нет потребителя: DEFER; без выдуманного охвата или пользы                         |
| Семантическое замыкание   | Зафиксированная версия/конфигурация, прямые/транзитивные helpers, макросы, callbacks, shared state, transport, firmware и feature negotiation   | Неизвестное замыкание: DEFER; несовместимое неограниченное замыкание: STOP COMPAT |
| Native authorization      | Эффекты каждого caller, область grants/delegation/revocation, бюджеты и узкое native enforcement                                                | Расширение прав или необходимость Linux semantics в EL1: REJECT адаптера          |
| Lifetime и containment    | Остановка admission, attribution принятых запросов, quiescence callbacks/IRQ/DMA, reset, поколения restart/rebind и правдивые terminal outcomes | Непроверенная гарантия: DEFER; timeout как retirement или слепой replay: REJECT   |
| Альтернативы              | Сравнение ограниченного адаптера, native rewrite, отсрочки и отсутствия поддержки при равных гарантиях                                          | Выбрать решение для каждого случая; популярность и число API не решают            |
| Владение и выход          | Названный maintainer, окно review, план updates/churn, цель миграции, зависимости удаления и falsifiers                                         | Нет владельца или исполнимого плана выхода: DEFER supported status                |
| Стоимость и проверяемость | Лимиты ресурсов выбранного workload, измеренные либо неизвестные расходы и воспроизводимые negative/rollback tests                              | UNKNOWN остаётся UNKNOWN; скорость не отменяет провал security gates              |

REJECT означает нарушение условия данным предложением адаптера; это не означает вечного отсутствия поддержки оборудования. DEFER означает, что недостающие свидетельства/контракт препятствуют admission. UNSUPPORTED — явное решение о продуктовом scope после рассмотрения реальной потребности и возможных альтернатив; одного отсутствия свидетельств недостаточно. Native rewrite также подчиняется условиям аппаратной изоляции, lifetime и authority.

## Выбор бюджетов без универсальной оценки

Будущий владелец потребителя и рецензент native-контракта должны заранее задать полезный workload, concurrency, device features и исходы операций. Лимиты memory/request/queue/state выводятся из разрешённых grants и возможностей обработки отказов; latency/throughput/tail limits — из требований этого workload. До принятия сравнения фиксируются rationale, measurements, compiler/configuration, сырые receipts и область потерь. Оценки трудозатрат требуют разложения dependency/migration/test/maintenance work и указания оценщика; здесь обе оценки UNKNOWN. Произвольного порога числа драйверов и взвешенной security score нет.

Сравнивать равные authority, buffers, queue depth, cancellation/reset и полезные результаты adapter/native путей. Учитывать IPC, exclusive CPU, copies, memory, tail behavior, dependency churn, support и removal costs. Использовать [политику benchmark](../../../../docs/architecture/benchmarking.md); быстрый адаптер допустим только после прохождения гарантий. Если измеренный путь быстрее, сохранить результат. Аппаратные требования DMA/cache/ordering сохраняются для обеих альтернатив и не становятся автоматически долгом COST-L.

## Случай A: VirtIO block, узкое исследование boot target

**Наблюдаемые механизмы Linux.** [Построение запросов, строки 140–158](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/block/virtio_blk.c#L140-L158) использует scatterlists и virtqueue с GFP_ATOMIC. [Configuration work, строки 948–960](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/block/virtio_blk.c#L948-L960) откладывает обработку конфигурации. [Удаление/freeze, строки 1564–1607](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/block/virtio_blk.c#L1564-L1607) дожидается work, сбрасывает устройство и удаляет очереди; freeze также замораживает block queue. Это разные обязанности синхронизации, а не взаимозаменяемые API-заглушки.

**Предлагаемый scope, не выполненная конфигурация.** Исследовать один transport QEMU virt ARM64, фиксированные negotiated features и ограниченные read/write/flush requests для названного будущего block consumer. Transport, backend persistence, владение очередями и защита ещё не установлены. Исключать zoned operations, discard/write-zeroes и необязательное power-management поведение можно только при правдивом отклонении контрактом negotiated feature/configuration; исходник всё ещё содержит эти пути. Сборка Linux, применимость к физическому оборудованию и полное замыкание helpers не заявлены.

**Историческое обоснование.** Повторное использование Linux blk-mq, scatterlists, feature negotiation и deferred work разумно позволяет драйверу взаимодействовать с существующей block infrastructure и асинхронно меняющимися устройствами. Это вывод из проверенного текущего исходника, а не доказательство мотива первоначального автора или даты происхождения. GFP_ATOMIC предполагает ребро allocation-context к CANDIDATE COST-L-0001; принятого native behavior и полных свидетельств повторяемости пока нет. Нельзя выводить долг sysfs/ioctl или подтверждённую несовместимость из имени драйвера.

## Случай B: USB mass storage, семантика существующих подсистем

**Наблюдаемые механизмы Linux.** [Получение ресурсов, строки 855–883](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/usb/storage/usb.c#L855-L883) выделяет URB, вызывает device-specific initialization и запускает control thread. [Disconnect/освобождение ресурсов, строки 887–973](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/usb/storage/usb.c#L887-L973) останавливает scanning/admission, удаляет SCSI host, будит/останавливает thread и освобождает coherent buffers/references. [Обработка quirks, строки 675–725](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/usb/storage/usb.c#L675-L725) обрабатывает protocol/transport overrides и device flags. Bulk-only scope не может молча обещать все USB storage transports или quirks.

**Предлагаемый scope, не утверждение об устройстве.** Рассмотреть будущее идентифицированное bulk-only device и конкретного read-only consumer после появления native USB transport contract. Исключить UAS, другие protocols, arbitrary SCSI commands, неизвестные quirks и writable persistence до отдельного review. Native USB host-controller DMA/IRQ/reset и device-disconnect semantics остаются зависимостями даже при малом числе прямых DMA symbols в этом файле. Реальное устройство не выбиралось и не инвентаризировалось.

**Историческое обоснование.** Существующие USB/SCSI infrastructure, control thread и quirk catalogue разумно сохраняют asynchronous command/disconnect behavior и нестандартное оборудование. Переписывание этих правил без свидетельств может потерять необходимое поведение. Это вывод о design rationale из текущего кода; точное историческое происхождение и применимость каждого quirk остаются UNKNOWN. [DMA guide](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/Documentation/core-api/dma-api-howto.rst) Linux уже задаёт mapping lifetime и barriers: тезис о всяком DMA как legacy с неявным lifetime опровергнут.

## Сравнение решений и доверие по отдельным свойствам

| Измерение                       | VirtIO block                                                                                                                                | USB storage                                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ограниченный адаптер            | Импортировал бы выбранные blk-mq/virtqueue/feature/work semantics; замыкание не установлено                                                 | Мог бы сохранить ценные device quirks, но USB/SCSI/thread/URB closure не разрешено                                                                  |
| Native rewrite                  | Предпочтительное следующее design comparison для узкого QEMU block workload с fixed features; не одобренная реализация                      | Может сократить Linux subsystem dependence, но требует восстановления проверенных command, quirk и disconnect behavior                              |
| Текущее решение                 | DEFER обеих реализаций; приоритет исследованию native contract                                                                              | DEFER; сначала определить реального consumer/device и native USB transport scope                                                                    |
| Отсутствие поддержки            | Не выбрано: consumer/product scope не рассмотрен                                                                                            | Исключённые transports/commands не поддерживаются только в предлагаемом subset, а не по всему проекту                                               |
| Shared state / async lifetime   | Requests, queues, feature/config work, backing storage и device reset                                                                       | URBs, SCSI host/commands, scan work, control thread, power refs и disconnect                                                                        |
| Churn / firmware / architecture | Важны Linux helper/config revisions; firmware и реальный transport UNKNOWN; направление ARM64 релевантно                                    | Важны quirk/transport/subsystem revisions; firmware, применимость к ARM64 hardware и controller contracts UNKNOWN                                   |
| TCB по свойствам                | Для memory: DMA enforcement и queue/mapping retirement; для authorization: block effect attribution; для durability: flush/backend contract | Для memory: controller isolation и URB/buffer retirement; для authorization: command/device grants; для durability: device/SCSI completion contract |
| Трудозатраты / runtime cost     | UNKNOWN для обеих альтернатив; нет реализации или сравнимых измерений                                                                       | UNKNOWN для обеих альтернатив; нет реализации или сравнимых измерений                                                                               |
| Native migration target         | Рассмотренный bounded block service над узко допущенным transport enforcement                                                               | Рассмотренный bounded USB transport плюс явно ограниченный storage service                                                                          |

Compatibility domain может находиться вне EL1 и участвовать в TCB для authorized effects или data correctness. Containment его CPU memory fault не останавливает неизолированный DMA engine. Firmware и внешнее поведение device/backend влияют на разные свойства; перечислять trust assumptions для каждого свойства вместо подсчёта компонентов в одну security score.

## Отклонение, чувствительность и опровержения

Отклонять предложение портировать любой из двух полных Linux drivers через helper-заглушки, выдавать arbitrary command capability, считать timeout доказательством queue/DMA retirement или повторять неизвестный write после restart. Проверенные исходники явно зависят от stop/drain/reset ordering; удаление обязанности ради малого shim не является bounded adapter. При существующей native boundary необходимость Linux reclamation/USB/SCSI policy в EL1 означает STOP COMPAT, а не разрешение растить ядро.

Для VirtIO block установленный native transport и fixed consumer могут превратить DEFER в рассматриваемый native design. Обязательный Linux-specific external contract или доказанное reuse с полным bounded closure могли бы склонить выбор к адаптеру. Новые обязательные zoned/PM/transport features делают subset comparison недействительным. Для USB storage доказанно необходимый device quirk может склонить выбор к bounded reuse; стандартное проверенное устройство и native USB service — к rewrite. Требуемый неизолируемый controller, неизвестные reset effects или отсутствие retirement evidence сохраняют отсрочку обеих альтернатив либо мотивируют явное unsupported decision. Только source-reference reach не меняет решения.

Спецификации будущих negative tests: отозвать caller во время admission; disconnect при accepted requests; задержать callback до завершения restart; нарушить reset; удержать DMA mapping; отправить excluded feature/command; подменить buffer другого consumer; повредить completion; потерять provenance/coverage. Требовать отсутствия unauthorized effect и premature reuse, generation-safe rejection и правдивого failure/unknown outcome. Это не выполненные результаты; host/schema tests не устанавливают device quiescence.

## Владение review и предварительные условия

Подготовка исследования завершена для этого ограниченного сравнения; adoption owner и implementation/support maintainer — UNASSIGNED.
