# База инженерных случаев

Каждая запись — файл `KOL-PATH-NNNN.json`. Не использовать повторно выведенные идентификаторы; заменять записи с сохранением истории Git. См. [схему](../../../../schemas/pathology/case.schema.json) и [указатель случаев](../../docs/research/CASE_INDEX.md).

База включает дефекты, необходимые аппаратные ограничения, успешные переработки и принятые компромиссы. `category` может содержать несколько классификаций; `kolvrt_decision` содержит одно решение. NATIVE_FIX означает предотвращение проблемы в собственной модели, а не реализованное исправление KOLVRT. COMPAT_ONLY не разрешает ненужный модуль. HARDWARE_TRANSLATION может быть необходимо собственной целевой платформе.

ANALYZED_WITH_OPEN_QUESTIONS означает законченный документальный разбор с указанными ограничениями, а не воспроизведённую ошибку или полную историю Git. Уверенность MEDIUM включает непроверенную применимость к будущему KOLVRT. HIGH требует дополнительной исторической проверки или соответствующего воспроизведения; проверка схемы не повышает уверенность.

`first_known_version` может обозначать подтверждённое изменение или альтернативу вместо первоначального введения; текст уточняет значение. Неизвестное введение обозначается null с открытым вопросом. Даты источников не являются датами исследования. `linux_current_solution` описывает решение, подтверждённое прочитанным источником, а не каждым последующим выпуском Linux.

## Исследовательские вопросы

| Вопрос | Поля |
|---|---|
| Что произошло? | observable_behavior, root_cause |
| Когда? | historical_context, linux_versions, first_known_version, sources |
| Почему? | original_reason |
| Тогдашние ограничения | constraints_then |
| Нынешние ограничения | constraints_now |
| Классификация | category, root_cause |
| Последствия изменения | change_consequences, compatibility_dependency |
| Ответ Linux | linux_current_solution |
| Возможность улучшения | improvement_assessment, remaining_problem |
| Решение KOLVRT | kolvrt_decision |
| Собственная семантика | kolvrt_native_semantics |
| Потребность в совместимости | compatibility_required, compatibility_scope |
| Нужно ли вообще? | kolvrt_decision, migration_strategy |

`evidence` связывает исторические поля с идентификаторами источников. Оценки влияния являются инженерным анализом, а не измеренными результатами KOLVRT или цитатами разработчиков. Проектные решения, необходимые тесты и измерения являются требованиями проекта. Объяснять неприменимость измерения вместо пустого списка.

При изменении записи проверить источники, указатели, происхождение, решение, уверенность и последствия для миграции и тестирования. Выполнить проверку и обновить двуязычный указатель по [руководству инструментария](../../tools/research-checks/README.md). Проверки не устанавливают истинность источников и не заменяют рецензирование. Исходный исследовательский текст JSON сохраняется; английские и русские Markdown используют проверенный текст указателя.
