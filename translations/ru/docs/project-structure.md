# Структура репозитория

Структура разделяет собираемые программы, нормативный проект, обоснования решений и исследовательские данные. Пустые каталоги ядра и драйверов до появления реализации не добавляются.

```text
crates/
  native-protocol-model/   # кандидат запросов и ответов без стандартной библиотеки
  native-state-models/     # конечные модели и эксперимент межпроцессного обмена
  repository-checks/       # схема, ссылки, законы, переводы и отчёты
docs/
  architecture/           # контракты и проверяемые спецификации
  architecture-decisions/ # обоснования, альтернативы и последствия решений
  research/               # методы, указатели, отчёты и недостающие свидетельства
research/
  cases/                  # структурированные исторические свидетельства
  sources/                # реестр происхождения и двуязычный каталог
  results/                # воспроизводимые результаты моделей и прослеживаемость законов
  requests/               # исходные свидетельства запроса
schemas/                  # контракты проверки данных
translations/ru/          # зеркальные пути документов Markdown
```

## Обоснования и альтернативы

[Cargo рекомендует плоский каталог пакетов](https://doc.rust-lang.org/cargo/reference/workspaces.html) рабочего пространства. Один корневой файл фиксации зависимостей и каталог сборки обслуживают все три пакета. Имена пакетов описывают назначение; суффикс модели не даёт принять прототип за реализацию ядра. Отдельное дерево инструментов и исполняемые пакеты среди исследовательских данных добавляли места без отличающегося жизненного цикла сборки, поэтому они объединены.

[Записи решений](https://adr.github.io/) сохраняют причины выбора и компромиссы; спецификации описывают получившийся контракт. [Diataxis](https://diataxis.fr/) разделяет назначения документации. Проект применяет это различие без выдумывания пустых учебных каталогов и без утверждения, что подход предписывает именно это дерево. Руководство участника — практическая инструкция; контракты — справочный материал; решения объясняют выбор; исследовательские отчёты фиксируют свидетельства.

Markdown использует описательные имена в нижнем регистре с дефисами, кроме общепринятых README.md и CONTRIBUTING.md. Постоянные идентификаторы случаев сохраняются. Документ имеет одно основное место и ссылается на связанные материалы; факты не дублируются между указателями. Переводы повторяют исходные пути, а машинные записи остаются единым источником. Реестр переводов и формируемый указатель случаев проверяют соответствие.

## Проверка изменений

Новый пакет требует отдельной обязанности или границы зависимостей. Новый каталог требует существующего содержимого с отдельной ролью. Перемещение одновременно обновляет ссылки, пути проверок, соответствие переводов и команды. Форматирование автоматическое через [порядок участия](../CONTRIBUTING.md). Локальные кеши и результаты сборки исключены из контроля версий.
