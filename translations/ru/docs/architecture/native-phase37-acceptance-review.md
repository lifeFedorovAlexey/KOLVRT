# Приёмочная проверка native-приложений Phase 3.7

Document status: HISTORICAL MILESTONE
Evidence scope: проверка исходников, кода, архитектуры и соответствия EN/RU, выполненная Codex по запросу сопровождающего для реализации 7f8dd80f6a322a4654994fc1aa3ed44beaefdd10, проверенной основы bf54960925559d8925c24b6d40e557e98af08f41 и независимо проверенных текущих артефактов CI. Независимое человеческое одобрение, доверие для production, проверка физического ARM и приёмка производительности не заявляются.
Current reference: [Native-приложения](../kernel/native-applications.md)

## Решение и границы

Принять первый ограниченный сценарий native-приложений для issue #28: исходные отдельные ELF управляющего процесса, сервиса счётчика и клиента, приватное состояние EL0 между запросами, native IPC, настоящее восстановление с новой instance и штатное освобождение ресурсов сессии. Это приёмка ограниченной реализации, отдельно от готовности к production. Native-интерфейсы остаются EXPERIMENTAL и незамороженными; оборудование — UNKNOWN. Файловая система, сохранность данных на диске, произвольный spawn, пакеты, сеть и поздние этапы исключены.

Полный CI [37557806495](https://github.com/lifeFedorovAlexey/KOLVRT/actions/runs/37557806495), привязанный к исходникам, прошёл четыре shard, все 144 запланированные и выполненные задачи, сбор evidence, native, host, routing, ASID и lint обоих профилей. Dependency hygiene прошёл отдельно. [Receipt](../../../../research/results/native-phase37-current.json) сохраняет восемь исходных артефактов с хешами байтов, 151 совпадающий входной файл и точное происхождение checkout. Семь входов workflow и инструментов выделены отдельно от плана гостя; их проверка не описывается как компиляция гостевого кода. Исходные артефакты имеют суффикс .receipt для сохранения байтов JSON и значений u64.

## Время и целостность тестов

Production coordination требует настоящих acquired completion, detached roots, released owners и дренирования copy/source/ack. Произвольного timeout для completion-publication/copy-drain нет; опубликованный CPU FAILED останавливает работу с удержанием ресурсов. Молчаливые зависания требуют внешней диагностики и никогда не разрешают reclaim. Watchdog начальной загрузки ELF находится снаружи; канонический backoff supervisor и readiness /8 в assembly сохранены. Quantum fixture инициализирует сравниваемый вход x20/TPIDR до любого IRQ и сохраняет проверки настоящего выполнения и роста, точных результатов, восьми квантов, контекста и ресурсов.

Исторический 3873bc8 наблюдал expiry worker Submit до admission: 127.22 ms против абсолютного предела политики 125 ms. Запрос не достиг сервиса; это не устанавливает медленный ответ или дефект производительности планировщика. Диагностика CLOCK residency сохранена, текущий полный запуск прошёл без увеличения /8. Ограниченная функциональная приёмка не является гарантией реального времени, всеобщего отсутствия гонок или выводом, что все исторические ошибки времени исправлены.

Внешний наблюдатель отказа различает уникальные replies по паре receiver/service-token и повторные остановки до SVC, требуя новый COMMIT token. Обычное завершение W00 без выбранного fault по-прежнему отвергается. Host-тесты проверяют учёт повторных остановок; настоящий журнал fault/completion/replacement/client/shutdown остаётся строгим. Повторы до зелёного результата, скрытые задержки гостя и изменения копий исходников не используются.

## Проверка смысла и перевода

Проверены поведение production SDK и приложений, выбор и загрузчик исходного ELF, начальные grants и происхождение caller, lifecycle binding/retirement, acquired дренирование scheduler/SMP/IPC, текущая классификация входов проверок, разрешение workspace и инструментов, настоящие внешние клиенты публичного ABI. Полные изменённые пары EN/RU native, supervision, process, IPC, scheduler, SMP, CI, law/ADR и README прочитаны по этим исходникам. Оба языка сохраняют одинаковые ограничения, значения полей, историю конкретных исходников и исключения. Запись хешей перевода и repository checks устанавливают механическую согласованность; это авторское сравнение с исходниками даёт отдельную проверку смысла.

## Оставшийся объём

Физический ARM, production authorization/trust образов (#38), сохранность данных на диске и при отказе, произвольные creation/migration, восстановление при любом startup/post-commit crash и допустимость изменений производительности не приняты. Эквивалентность мутациям missing-publication/missing-ACK/skipped-TLBI/restore не заявляется. Эти более широкие сценарии не переопределяют выполненные результаты первого slice. Issue #28 может использовать эту ограниченную приёмку и evidence точных исходников; состояние merge/PR проверяется отдельно.
