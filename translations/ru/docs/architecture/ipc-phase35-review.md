# Повторное выведение архитектуры IPC Phase 3.5

Document status: CURRENT
Evidence scope: архитектура повторно выведена от origin/main `7c8ed152fb3ed5fa1c996f6b447396ad6aa0caca`; реализация и QEMU evidence соответствуют этому набору исходников. Выборы E1/A записаны в ADR-0025.
Current reference: [Текущий контракт scheduler](../kernel/scheduler.md)

## Основание review и граница решения

После архитектурного review пользователь поручил продолжать до полной реализации Phase 3.5, тестов, документации и PR. Реализация использует execution option E1 и synchronization option A. ADR-0025 фиксирует выбранные invariants; это review сохраняет сравнение вариантов и не закрывает #26.

Сохранённая реализация включает endpoint/request arbiter, initialized copied frames, scoped grants, transactional receive/collect, wake/ack mailboxes и continuous idle/resume. Исходный технический receipt содержит 124 проверки каждого DEV/PROD профиля и 46 IPC mutation runs с точным expected event. После integration с main 658cd22 оба положительных профиля снова прошли все 124 проверки; отдельный receipt различает текущие наблюдения и исторические свидетельства неизменённого enforcement. Сохранён performance baseline из 144 групп каждого профиля. Итоговое acceptance review остаётся открытым.

Периодически обновляемые origin/main и work branch начинаются с `7c8ed152fb3ed5fa1c996f6b447396ad6aa0caca`. Исходный checkout оставлен без изменений; его локальная документация исключена из review. GitHub issue [#26](https://github.com/lifeFedorovAlexey/KOLVRT/issues/26) остаётся открытым; [#75](https://github.com/lifeFedorovAlexey/KOLVRT/pull/75) и [#76](https://github.com/lifeFedorovAlexey/KOLVRT/pull/76) merged. [#27](https://github.com/lifeFedorovAlexey/KOLVRT/issues/27) и [#28](https://github.com/lifeFedorovAlexey/KOLVRT/issues/28) остаются последующими service gates.

Решение для execution architecture принято: IPC добавляет continuous owner-local idle/resume и сохраняет retirement всей session. Непрерывный idle owner не считается quiescent только из-за отсутствия READY процесса. Kernel сохраняет fixed affinity, exclusive scheduler access и immutable mappings; independent CPU sessions, migration и retirement отдельных процессов остаются вне milestone.

Execution option E1 и synchronization option A сохраняют fixed affinity, exclusive scheduler access, immutable mappings и консервативный retirement barrier. Continuous execution mode и split syscall continuation записаны в ADR-0025. Существующие dispatch/step fixtures сохраняют отдельный scope. Independent admission, retirement отдельных процессов, migration и supervisor policy исключены.

## Решение об execution architecture

Все три варианта требуют настоящей timer/SGI wake handling, когда runnable tasks отсутствуют. Одно добавление atomic queue внутри текущего callback этого не реализует. Synchronization alternative B можно совместить с E1 или E2; сам по себе он не разрешает execution lifetime.

| Измерение           | E1: continuous owner-local IPC execution, retirement всей session                                                                                                                                                      | E2: independent CPU sessions и retirement отдельных процессов                                                                                                                             | E3: coordinator-owned event-driven step pump                                                                                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Correctness         | Каждый owner удерживает admitted namespace/context во время idle. Отсутствие READY task означает native idle с timer/mailbox recheck, а не Done. Оба CPU acknowledgements и unlink всё ещё предшествуют frame release. | Каждому process нужны retained scheduler/root leases и owner-local detachment acknowledgement независимо от peer execution. Переписать whole-session detached/namespace-return semantics. | Оба CPUs отсоединяются после каждого bounded step; coordinator владеет contexts/namespaces, пока спит в ожидании events. Mailbox должен будить coordinator, а не изменять completed Local. |
| Security            | Сохранить exact generation, fixed affinity, current-copy proof, no-lock storage scopes и global retirement safety. Idle не может публиковать ложный completion.                                                        | Новые lookup, admission и reclaim races влияют на address-space lifetime, ASID reuse и перемещение handle owner. Нужен новый retained-root proof по ADR-0017/0018/0021.                   | Сохранить conservative retirement safety; admission контролирует один coordinator. Deferred records должны различать active и detached namespace ownership.                                |
| Performance         | Убрать whole two-CPU handoff на каждый IPC wait/wake; barrier остаётся для session completion. Reclamation ждёт session quiescence.                                                                                    | Убрать global retirement coupling и разрешить admission при выполняющихся peers; выросшие synchronization/lease overhead нужно измерить.                                                  | Per-step rendezvous и namespace handoff остаются в execution path. Peer preemption и IPC latency зависят от coordinator wake/drain scheduling.                                             |
| Complexity          | Добавить native idle/resume, next-deadline scheduling и generation-safe owner mailbox; сохранить existing retirement protocol.                                                                                         | Самое большое lifecycle change: safe retained roots, per-process acknowledgements, independent namespace ownership и concurrent registry operations.                                      | Новый coordinator idle/timer protocol, targeted owner restart и wake records между dispatch generations. Проще reclamation, больше wake cases на границах rounds.                          |
| Будущая scalability | Поздний per-process retirement может улучшить scalability без изменения IPC identity/outcomes. Supervisor policy остаётся #27.                                                                                         | Более сильный foundation для concurrent admission/reclamation, но существенно расширяет Phase 3.5.                                                                                        | Coordinator остаётся bottleneck; для independently persistent services может понадобиться замена execution pump.                                                                           |
| Compatibility       | Сохранить synchronous dispatch/step fixtures и их historical scopes; добавить отдельный continuous IPC path. Новый execution contract требует ADR, но не ослабляет storage exclusion и не замораживает ABI.            | Явно заменить conservative retirement portion ADR-0017 и соответствующие current-copy/namespace assumptions.                                                                              | Сохранить step semantics; обобщить coordinator signals и добавить настоящий event-driven sleeping. Не выдавать current bootstrap polling за production idle.                               |
| Reversibility       | Private execution mode может позднее использовать independent retirement после equivalent quiescence evidence.                                                                                                         | Самый сложный rollback после того, как lifecycle callers станут зависеть от concurrent admission и independent completion.                                                                | Private pump можно заменить при сохранении IPC correctness; сначала нужно drain всех mailbox reservations.                                                                                 |

Рекомендация: E1 для Phase 3.5. Принимаемое изменение должно ограничиваться continuous execution/idle и split syscall continuation. Не ослаблять whole-session frame retirement barrier, не добавлять migration или supervisor/restart policy. E2 требует отдельного retained-lifecycle architecture decision. E3 — допустимая conservative alternative, но она обязана реализовать настоящий event-driven sleeping и владеть explicit wake handoffs на границах sessions.

Исходный execution decision gate разрешён принятым выбором E1/A в ADR-0025; варианты выше сохраняются как запись сравнения архитектур.

## Предлагаемый transport contract после решения

Endpoint — отдельный concrete primitive. Его immutable identity/generation, exact bound service generation, fixed-affinity CPU, owner/domain charges, capacity, admission state и retained references не являются user-selected authority. Caller-local SEND grant допускает requests. Receiver authority — explicit nondelegable bootstrap-installed endpoint binding в service namespace плюс exact service-generation validation; одного PID equality недостаточно. Delivered request token разрешает только commit/reply для своих exact endpoint/request/service generations. RECEIVE/REPLY rights не предлагаются без отдельной доказанной authority distinction.

Рекомендованная замена candidate — отдельно versioned experimental transport contract с сохранением LE64 handles с настоящим encoding 8/56. native.request/0 остаётся обозначенным superseded host proposal до совместного обновления его lifecycle/consumer record и host fixtures. Это review не установило внешнего production consumer; отсутствие в host fixture не доказывает отсутствие consumers повсюду. Явно отвергать unsupported versions и сохранять отсутствие ABI-FREEZE.

Endpoint lifecycle: Vacant → Bound → Live → Closing → Retiring → Vacant со строго большей generation. Slot exhaustion переводит storage в quarantine. Admission закрывается до shutdown terminalization. Handle close/revoke прекращает future lookup/admission без cancellation accepted requests или delegated references.

Request lifecycle: reserved unpublished storage → QUEUED → DELIVERED → optional COMMITTED → один terminal result → successful collection или explicit cleanup → retired. Каждый accepted request владеет initialized bounded payload/response storage, immutable snapshot length, endpoint reference, consumer domain request charge, service queue/active charges, deadline и exact service-token generation. Failed admission откатывает всю ownership без публикации ID или waiter.

| Event, выигравший arbiter           | QUEUED или DELIVERED до commit            | COMMITTED                                                      | Уже terminal                                                |
| ----------------------------------- | ----------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------- |
| Valid service reply                 | COMPLETED с initialized response          | COMPLETED с initialized response                               | Отвергнуть stale/duplicate reply; сохранить original result |
| Consumer cancellation               | CANCELLED_BEFORE_EFFECT                   | EFFECT_UNKNOWN; никогда не заявлять rollback                   | Explicit already-terminal result; без второго wake/release  |
| Absolute deadline                   | EXPIRED_BEFORE_EFFECT                     | EFFECT_UNKNOWN                                                 | Сохранить original result                                   |
| Service death или endpoint shutdown | CANCELLED_BEFORE_EFFECT с truthful reason | EFFECT_UNKNOWN, если completion ещё не выиграл                 | Сохранить original result                                   |
| Consumer death                      | Cancel before effect и abandon delivery   | Удерживать ownership до terminal resolution; без user delivery | Освободить abandoned receipt ровно один раз                 |

No-effect guarantee относится к authorized commitment boundary transport. Она не устанавливает durability и не откатывает arbitrary external actions. Будущие device/storage/network services должны связать собственный irreversible-effect boundary с этим контрактом; kernel не анализирует application semantics и не устанавливает service discovery/restart policy.

Receive/collect transactional: резервировать exact queued/result generation, полностью скопировать executing service/client под current Access, затем commit dequeue/consumption. Ошибка сохраняет queued request/result, если concurrent independent cancellation/death законно не делает его terminal. Token, скопированный непосредственно перед cancellation, впоследствии должен отвергаться arbiter. Copy error не может создать successful delivery или consume client ID.

Wait identity включает exact ProcessId, endpoint/request generation, wait sequence и kind. Check condition → publish registration → recheck → publish BLOCKED только при false. Producers публикуют condition/result до wake record. Только target owner проверяет record и меняет BLOCKED на READY; stale/duplicate records не создают другого running owner. One active blocking reason per process и one authorized endpoint receive waiter — explicit bounds. Idle entry должен повторно проверить pending records после registration и перед sleeping.

Использовать Release publication и Acquire observation для queue/result bytes и mailbox records; синхронизировать arbiter transitions и reservations явным AcqRel CAS или reviewed endpoint permit. Retirement endpoint/token generations требует acquired final ownership release и отсутствия queued, delivered, terminal, waiter и mailbox references. Timeout никогда не является teardown acknowledgement. Deadlines — absolute boot-local counter ticks с checked conversions, отличные от CPU-slice budgets. Nearest deadline должен оставаться armed при idle owning CPU; IRQ публикует bounded deferred expiry, а deferred path использует тот же terminal arbiter.

Initial payload bound — 256 bytes, с capacity-1 и capacity-4 endpoint configurations. Queue order — successful admission linearization, а не wall-clock ordering CPUs. Request budgets отдельно учитывают consumer outstanding work и service queued/active work; моменты release следуют настоящей ownership. Endpoint pool storage требует explicit quota dimension или явно bounded/bootstrap-owned reserve; не использовать молча unrelated quota. Safe baseline имеет четыре payload copies: client → kernel request → service, затем service → kernel response → client.

## Reuse, замена и acceptance obligations

Reuse только generation-safe process/handle/domain identities, current Access/Snapshot, attenuated SEND/TRANSFER/REVOKE rules, retained domain Charges, fixed-affinity running-owner checks, precise copy fault recovery и owner-local ASID retirement. Сохранить Event как coalescing notification primitive. Его retained-pool approach — evidence для bounded lifetime, а не endpoint queue или automatic IPC-wakeup implementation.

Заменить security.rs single-cell Work/Receipt model для general IPC отдельными endpoint/request storage, service receive, transactional collect и одним terminal arbiter. Сохранить native.notification/1, только если его существующий bounded independent contract остаётся полезным; removal или refactoring должны сохранять truthful historical evidence и current feature status. Это review не удаляло и не refactor код.

Реализация покрывает payload, authority, queues, waits, SMP, cancellation/deadline, death, accounting и reclamation реальными EL0 fixtures. Итоговая acceptance проверяется по исходному заданию; physical ARM остаётся UNKNOWN и не выдаётся за QEMU evidence. Новый IPC storage содержит проверяемый Cell Sync и HRTB unsafe access; отдельные unsafe диапазоны относятся к immutable linked EL0 images и контекстам исполнения. Inventory не является safety proof.

EN/RU contracts, ADR-0025, unsafe inventory, stable IPC section IDs, enrollment/catalog/graph и generated README summaries уже обновлены. IPC остаётся EXPERIMENTAL до закрытия оставшихся acceptance gates. #26 остаётся открытым; следующий supervisor gate — #27, затем persistent-service gate #28.
