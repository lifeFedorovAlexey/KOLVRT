# Методика измерений при переходе

Document status: DESIGN BASELINE
Evidence scope: требования к измерениям и воспроизводимости; новых результатов выполнения не заявлено.
Current reference: [ADR-0006](../architecture-decisions/0006-metrics.md)

Это методика, а не результаты измерений. Собственные интерфейсы не считаются заранее
быстрее. Искусственные задержки, разные квоты и ослабление безопасности одной стороны
запрещены. Более быстрый путь совместимости отражается честно и становится основанием
для анализа собственного пути.

## Контракт эксперимента

До запуска определить нагрузку, критерий корректности, различия поведения, основную
метрику, интенсивность запросов и правило остановки. Сравнивать эквивалентный полезный
результат. Буферизованная запись и запись на устойчивый носитель дают разные гарантии;
стоимость преобразования поведения оценивается отдельно, а не скрывается в отношении скоростей.

Использовать одинаковые данные, ограничения ресурсов, области планирования, правила
памяти и устройства. Между парными запусками восстанавливать исходные условия. Внешние
действия воспроизводить в независимых снимках, не дублируя реальные записи, сообщения или
платежи. Чередовать A/B и B/A либо случайно выбирать порядок с сохранённым начальным
значением генератора. При измерении изолированной задержки не создавать конкуренцию за одно устройство.

Сохранять точные контрольные суммы ядра и адаптеров, описания маршрутов, параметры
компилятора и компоновщика, версию, машину, процессор и ускоритель эмулятора либо ревизию
оборудования и прошивку, память, число процессоров, привязку, частотную политику,
температуру, распределение прерываний, фоновую нагрузку и измерительные средства.
Разделять холодный запуск и установившийся режим. Пропускная способность эмулятора не
определяет её на кристалле. Привязку процессоров применять симметрично.

## Выборка и статистика

Заранее определить допустимые отклонения при прогреве, окна наблюдения и предельную
длительность. Помеченные данные прогрева сохранять отдельно. Отсутствие стабилизации
делает запуск недействительным, а не разрешает отбросить неудобные медленные наблюдения.

Размер выборки выбирать по требуемой неопределённости, наблюдаемой зависимости и полноте
наблюдения редких задержек с предварительным исследованием до основного эксперимента.
Фиксированное число запусков не гарантирует надёжный p99. Недостаток независимых запусков
или редких наблюдений означает недостаточность данных. Нельзя менять правило остановки
после обнаружения победителя; последовательный вывод требует отдельно заявленного метода.

Публиковать число наблюдений, длительность, медиану, p95, p99, среднее, выборочную дисперсию
и стандартное отклонение. Заранее закрепить оценку квантиля, например `sorted[ceil(p*n)-1]`.
Доверительные интервалы строить по независимым парным запускам или блокам с учётом
зависимости, а не считать связанные запросы независимыми. Показывать абсолютные разницы,
отношения и неопределённость. Отношение к нулю не определено. Распределение квантилей
отдельных запусков и квантиль общей выборки — разные статистики; среднее p99 не является общим p99.

Учитывать истечение срока, ошибки, отброшенные и незавершённые запросы. Показывать
ограничение наблюдений: для неполностью наблюдаемого хвоста возможна лишь нижняя граница.
Не скрывать выбросы. Исключение требует заранее определённого критерия недействительности,
причины и сохранения исходных данных. Публиковать все нагрузки и заранее заданные веса
обобщения. Допуски регрессий следуют из требований, а не подгоняются под полученную дисперсию.

## Измерения

| Измерение              | Определение                                                                            |
| ---------------------- | -------------------------------------------------------------------------------------- |
| Полная задержка        | От приёма до окончательного результата; отдельно ожидание очереди и обслуживание       |
| Пропускная способность | Успешные полезные единицы за секунду с указанием ошибок                                |
| Затраты процессора     | Исключительное время выполнения, относимая отложенная работа и отдельно такты          |
| Память                 | Собственные, общие и закреплённые байты и максимум; без повторного учёта общих страниц |
| Выделение памяти       | Число операций, байты, максимум живых данных, распределитель и распределение размеров  |
| Переключения контекста | Добровольные и вынужденные с указанием области планировщика                            |
| Копирования            | Число и байты на заявленных измеряемых границах                                        |
| Блокировки             | Захваты, число конфликтов и распределение времени ожидания                             |
| Преобразование         | Входы в адаптер, преобразования, байты сериализации и десериализации                   |
| Аппаратные счётчики    | Поддерживаемые события, кодирование, разделение счётчиков и ошибка выборки             |
| Стоимость наблюдения   | Парные запуски с измерениями и без них, число потерянных событий                       |

Нельзя вычитать шумную стоимость наблюдения и объявлять точное исправленное значение.
Нужно показывать неопределённость. Недоступные счётчики остаются недоступными. Затраты
адаптера, общей собственной службы и всей операции разделяются. Артефакт запуска содержит
описание условий, контрольную сумму нагрузки, результат проверки корректности, исходные
наблюдения, журнал исключённых запусков, версию анализа и отчёт. Средство измерений
реализуется лишь при наличии двух настоящих сравнимых путей. Записи случаев определяют
обязательства для конкретных нагрузок.
