# Модель маршрутизации

Общего переключателя совместимости нет. Профили выполнения не выбирают поведение.
Маршрут определяется при запуске или привязке; вызовы используют закреплённый результат,
а не ищут новую реализацию каждый раз.

## Определение маршрута

Ключ включает потребителя, семейство интерфейсов, протокол, версию поведения, возможность,
область состояния и при необходимости идентичность устройства. Пакеты задают исходные
требования; правила процесса сужают их; правила драйвера, устройства и администратора
добавляют ограничения. До выбора совместимого маршрута вычисляется пересечение прав.
Конфликты не решаются последней записью: неоднозначность требует явного правила выбора
либо отказа в привязке.

Привязка хранит собственные операции, цепочку адаптеров, версию поведения, контрольную
сумму реализации, замыкание зависимостей, область состояния, права, ограничения, профиль
и поколение. Неподдерживаемые семейства не переводятся молча на совместимость.
Маршрутизация не расширяет полномочия.

| Уровень                              | Первоначальная роль                                             |
| ------------------------------------ | --------------------------------------------------------------- |
| Пакет или исполняемый файл           | Заявленные требования к поведению и наследуемые значения        |
| Процесс                              | Поведение операционной системы, правила и связанные дескрипторы |
| Драйвер или устройство               | Протокол и ограниченное преобразование аппаратных особенностей  |
| Подсистема или семейство интерфейсов | Открытый выбор маршрута                                         |
| Протокол и версия                    | Неизменяемый контракт поведения                                 |
| Возможность совместимости            | Узкое отклонение с доказанной независимостью состояния          |

Начинать следует с конечной таблицы семейств, а не универсального графа маршрутизации.
Разделение отдельных возможностей требует решения с анализом общего состояния. Среда
совместимости на AArch64 не обещает выполнения инструкций x86 или AArch32.

## Общее состояние

Один процесс может использовать собственные интерфейсы памяти, файлов и сети со старым
адаптером синхронизации, другой — только собственные интерфейсы, третий — требуемый внешний контракт.
Этот пример допустим лишь при согласованной идентичности и времени жизни общей памяти.

Доступ к файлу, закрытие, дублирование, блокировки и подписки на события могут разделять
единый граф дескрипторов. Учётные данные, пространства имён и проверка полномочий образуют
область безопасности. Операции одного потока данных разделяют состояние протокола.
Эти связи ограничивают дробность маршрутизации.

Переданные дескрипторы сохраняют идентичность объекта и привязку поведения; исходные
правила получателя не переосмысливают существующее состояние. Перенос между областями
требует посредника, проверяющего права и поведение. Неподдерживаемые сочетания отклоняются.
Общим ресурсом управляет единый арбитр.

## Управляемый переход

1. Проверить поддержку перехода, эквивалентность поведения и полномочия оператора.
2. Остановить приём запросов во всей затронутой области состояния.
3. Завершить запросы, ожидания, обратные вызовы, блокировки и ввод-вывод; при истечении срока сохранить старую привязку.
4. Сделать снимок или явно преобразовать состояние и проверить его инварианты.
5. Атомарно опубликовать новое поколение привязки на всех входах области.
6. Возобновить приём; удерживать старый код до завершения ссылок и требуемых периодов ожидания читателей.

Ошибки до фиксации сохраняют старую область. Внешние действия ограничивают возможность
отката. Если преобразование или достижение покоя невозможно, требуется перезапуск.
Рабочий профиль не предоставляет экспериментального переключения во время выполнения.
Проверка полномочий обязательна и на быстрых путях. В фазе 0.2 необходимо моделировать
конфликты, понижение версии, передачу дескрипторов, одновременную перепривязку и выгрузку;
основания для этих проверок дают случаи 02, 03, 17, 18, 25, 26 и 30.
