# Контракт первой платформы

Проектная платформа — AArch64 EL1 с задачами EL0, младшим байтом первым, гранулами трансляции 4 КиБ и двумя процессорами. Состояние процессора и права таблиц страниц отделяют привилегированный код от задач; записываемые страницы не исполняются, а исполняемые не записываются. Пользовательские сбои завершают задачу; привилегированные останавливают исполнение вместо продолжения неизвестного состояния. Текущий [фундамент ядра](../kernel/boot.md) реализует EL1 на CPU0; задачи EL0 и активация вторичного CPU остаются последующими обязательствами.

## Воспроизводимая платформа

| Элемент                         | Выбранная основа                                                      | Проверка                                                        |
| ------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------- |
| Компилятор                      | Rust 1.99.0, коммит b940084d7eb6a299eb4bfeb8e34901bc051e7ac4          | Установлен и выполнен                                           |
| Основа компилятора              | LLVM 23.1.1 из комплекта компилятора                                  | Сообщена rustc -vV                                              |
| Цель                            | aarch64-unknown-none                                                  | Кандидат протокола без стандартной библиотеки успешно проверен  |
| Компоновщик                     | rust-lld из того же закреплённого компилятора                         | ELF DEV и PROD скомпонованы и загружены                         |
| Проектное закрепление эмулятора | QEMU 10.1.0, virt-10.1, cortex-a57, TCG, 2 процессора, 256 МиБ, GICv3 | Установлен; один активный CPU; настоящие kernel tests выполнены |
| Необязательные устройства       | В первом сценарии нет потребителя PCIe, диска, сети или DMA           | Включать только с контрактом устройства и тестами               |

Закрепление эмулятора — воспроизводимый проектный ориентир, а не рекомендация подвергать старый эмулятор враждебному гостевому коду. До исполнения проверить происхождение и совместимость выбранного исполняемого файла или явно пересмотреть закрепление. Не подменять незаметно на `virt`, `max`, ускорение основной системы или другую версию. Setup проверяет SHA-512 закреплённого Windows archive; [проверки ядра](../kernel/testing.md) записывают полную версию, аргументы и ELF digests. Аппаратное выполнение остаётся непроверенным.

## Обязательства границ оборудования

| Граница               | Необходимый контракт до публикации задач                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Описание загрузки     | Проверять полный объём дерева устройств, смещения, выравнивание, завершение строк и зарезервированные области до использования адресов                                        |
| Память                | Различать память устройств и обычную; завершать требуемую публикацию таблиц страниц и сброс трансляций до повторного использования                                            |
| Несколько процессоров | Запускать каждый процессор со своим стеком исключений; подтверждать сброс на всех участвующих процессорах до освобождения отображённой страницы                               |
| Прерывания            | Инициализировать распределитель, перераспределители и интерфейсы процессоров до разрешения доставки; распознавать, обслуживать и деактивировать источник в правильном порядке |
| Таймер                | Читать архитектурную частоту, использовать монотонную эпоху и проверяемые преобразования; перевзводить или маскировать источник до завершения уровневого прерывания           |
| Остановка             | Отзывать вход, останавливать прерывания и отложенные обратные вызовы, затем освобождать стеки и отображения; истечение срока не заменяет прекращение обращений                |

Документ не утверждает точную последовательность регистров или рецепт барьеров. Реализация должна прикреплять соответствующие положения архитектуры к каждой небезопасной границе и проверять порядок на настоящей платформенной реализации. Конечные модели основной системы предполагают атомарность своих переходов; они не являются моделью слабой памяти или аппаратным доказательством.

## Источники и ограничения

- [Документация платы QEMU 10.1.0](https://raw.githubusercontent.com/qemu/qemu/v10.1.0/docs/system/arm/virt.rst): выбранные процессор и GIC, поведение версионируемой платы и обнаружение по дереву устройств. Это обосновывает конфигурацию, а не измеренную производительность.
- [Спецификация Device Tree v0.4, плоский формат](https://raw.githubusercontent.com/devicetree-org/devicetree-specification/v0.4/source/chapter5-flattened-format.rst): двоичная структура и границы заголовка для будущего разборщика.
- [Руководство порядка памяти Arm 102336_0100_01_en](https://documentation-service.arm.com/static/62a304f231ea212bb662321d): разделы 2, 5, 6, 8, 10 и 11 различают порядок, завершение, область и синхронизацию инструкций. Руководство обосновывает явные обязательства, а не универсальную инструкцию барьера.
- [Программный обзор Arm GICv3/v4](https://documentation-service.arm.com/static/5f1068720daa596235e7f6ef): состояния прерываний и программная обработка. Обзор не заменяет положения архитектуры уровня регистров при реализации.
- [Цель Rust AArch64 без ОС](https://doc.rust-lang.org/rustc/platform-support/aarch64-unknown-none.html): поддержка цели без стандартной библиотеки. Фактическая идентичность компилятора закреплена выше, поскольку веб-страница может меняться.

Адрес руководства таймера Arm был недоступен при проверке. Его текст не объявляется прочитанным. Программирование регистров таймера, инструкции таблиц страниц и настоящее исполнение прерываний остаются явными условиями проверки реализации; проектный контракт не выдумывает их подробности.
