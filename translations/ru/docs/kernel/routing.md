# Контракт маршрутизации в исполнении Phase 2

Document status: CURRENT
Evidence scope: ограниченная необязательная маршрутизация EL0 на проверенном фундаменте QEMU с двумя CPU; собственные IPC и службы не завершены.
Current reference: [Допуск и свидетельства](../architecture-decisions/0015-el0-versioned-routing.md)

Ограниченный сценарий версионированной маршрутизации и преобразования данных выполняется в восьми настоящих процессах EL0 на двух CPU. Разные потребители одновременно выбирают собственный формат, `inclusive-v1`, `counted-v2` и безопасный синтетический адаптер ошибочного поведения. Собственное ядро зависит только от `kernel-core`: оно не декодирует старые форматы, не выбирает версии совместимости и не вызывает адаптеры. [ADR-0015](../architecture-decisions/0015-el0-versioned-routing.md) фиксирует размещение, владение, безопасность и ограничения.

## Архитектура и границы репозитория

```text
xtask: проверить профиль → собрать выбранный пользовательский образ → проверить ELF → выбрать непрозрачную загрузочную полезную нагрузку
Супервизор CPU0: создать закрытые корни и стеки → открыть допуск
Потребители EL0 на CPU0: собственный / inclusive-v1 / counted-v2 / empty-first bug
Потребители EL0 на CPU1: собственный / inclusive-v1 / counted-v2 / empty-first bug
                    ↓ закрытый маршрут и синхронная операция
                    ↓ адаптер преобразует запрос в текущий собственный полуоткрытый интервал Span
                    ↓ собственный SVC; текущая очередь сообщает идентичность задачи
EL1: снимок учёта своей задачи → проверенное чтение интервала → инициализированный ответ в регистрах
EL0: общий собственный алгоритм сведения интервала → сумма и число слов
Оба CPU: собственный корень и завершённый TLBI → публикация Done
CPU0: получение Done от обоих CPU → проверка ограниченных отчётов → снятие учёта → освобождение кадров
```

```text
crates/kernel-core/src/execution.rs     native experimental operation contract
crates/kernel-core/src/window.rs        native checked algorithm and Backend boundary
crates/kernel/src/execution.rs          protected own observations and checked register reply
crates/kernel/src/scheduler/mod.rs          current-task attribution, SVC, admission
crates/kernel/src/memory/mod.rs         retained immutable RX image and guarded stacks
crates/routing/src/lib.rs               profile, versions, private binding and transactions
crates/routing/src/conformance.rs       behavior and rejection fixtures
crates/window-compat/src/lib.rs         optional legacy conversion and safe bug behavior
crates/routing-demo/                    separately linked no_std EL0 image
crates/xtask/src/routing_demo.rs         build, inspection, measurement and validation
```

```text
native kernel → kernel-core
EL0 demo → routing → kernel-core
                  → window-compat [optional, feature-selected] → kernel-core
host xtask → routing + kernel-core + evidence tools
native kernel ↛ routing or window-compat
```

Профиль с четырьмя записями — шаблон потребителя, независимо создаваемый на каждом CPU. Идентичность работающего потребителя задаётся собственным идентификатором задачи, а не слотом шаблона или переданным вызывающим селектором. Каждый экземпляр владеет отдельными структурами Rust `Consumer` и стеком. Общей изменяемой таблицы маршрутов нет.

## Native capability и authority

Обработчик таймера записывает ограниченные интервалы работы своей задачи в тиках `u32` с насыщением на `u32::MAX`. Фиксация сохраняет восемь наблюдений; повторный вызов не заменяет снимок. Ядро принимает проверенные границы полуоткрытого интервала `u32` и возвращает в инициализированных регистрах не более восьми собственных наблюдений; общий собственный алгоритм вычисляет в EL0 сумму и число слов. Память пользователя не разыменовывается, чужой владелец не принимается, корни таблиц страниц и привилегированные адреса не возвращаются. Пустые собственные интервалы дают ноль слов; неверная ширина, порядок или границы отклоняются до чтения данных.

Только привилегированный код может подтверждать принадлежащие ядру наблюдения планировщика и устанавливать текущую задачу. EL0 выполняет преобразование данных и применяет политику маршрутизации. На этапе загрузки каждой статической задаче предоставляется доступ только к её собственному полномочию на наблюдения и только на время её жизни. Это ограниченный контракт полномочий собственного ядра, а не общая реализация дескрипторов, capabilities или доменов безопасности. Адаптеры не могут расширить его. Все маршруты вызывают один обработчик; неподдерживаемое кодирование и отказ ядра не включают запасной путь.

Каждый адаптер использует один неизменяемый снимок принадлежащей ему записи. v1 преобразует включённые границы `LE16`, в том числе маркер пустого интервала из единиц; v2 преобразует проверенные начальную позицию и длину `BE32`. Необязательный адаптер ошибочного поведения трактует нулевую длину как одно собственное слово. Контролируемая демонстрация отличается от исправного результата для пустого интервала и не обходит проверку границ или раскрытие данных другой задачи. Сохраняется безопасное синтетическое поведение, а не настоящая историческая уязвимость.

## Владение, переключение и retirement

| Состояние                              | Владелец и возможность изменения                                   | Правило публикации и времени жизни                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Проверенный профиль и код пользователя | Доверенный выбор сборки и загрузки; неизменяемы                    | Сохранены точные контрольные суммы образа и профиля; загрузчик и замена кода во время работы отсутствуют                                 |
| Привязка и счётчики маршрутов          | Один потребитель EL0; изменяемое заимствование только у него       | Общих ссылок, доступа IRQ и записи с CPU0 нет; разные потребители работают на разных CPU                                                 |
| Операция и поколение                   | Закрытый потребитель; синхронные вызовы обработчика                | Объект-защитник удерживает привязку; в DEV переключение только после завершения; забытый объект блокирует допуск; переполнение запрещено |
| Собственная история и снимок           | CPU текущей задачи; IRQ замаскированы                              | Владелец не выбирается вызывающим; снимок неизменяем; ссылка Rust не переживает ERET                                                     |
| Сброс очереди и завершение             | CPU0 готовит; каждый CPU захватывает допущенный пакет через CAS    | `Idle → Admitted → Running → Done`; перед сбросом оба этапа завершения получены с acquire; устаревший опрос не возвращает очередь в Idle |
| Таблицы, страницы образа и стеки       | CPU0 владеет `Frame`/`UserSpace`; процесс использует закрытый стек | Учёт сохраняется при забытых объектах-защитниках; оба CPU восстанавливают собственный корень и завершают TLBI до освобождения            |

Синхронное сведение данных без сохранения состояния допускает переключение в DEV на границе операции. Перенос состояния, выгрузка модуля во время работы, перепривязка общих объектов и экспериментальное переключение в PROD отсутствуют. Для полномочия с состоянием нужны доказательство переходов либо перезапуск. Четыре страницы стека с неотображённой защитной страницей и не более 128 КиБ полезной нагрузки RX — явные загрузочные ограничения. Квант таймера остаётся типизированной настройкой собственного планировщика; исполнение образа ограничивают квант и предел допуска. Выделения памяти в IRQ и новые блокировки очереди или глобальной маршрутизации не используются.

## DEV API и production profiles

```text
cargo xtask routing test
cargo xtask routing status
cargo xtask routing inspect 1
cargo xtask routing compare 1
cargo xtask routing top
cargo xtask routing profile native,inclusive,counted,bug target/routing-profile.bin
cargo xtask routing validate target/routing-profile.bin EXPECTED_SHA256
```

Проверка просматривает сохранённые тестовые наблюдения; это не удалённый привилегированный инспектор. `Consumer::switch` и `Transaction::try_switch` — настоящий API DEV, проверенный в EL0. Текстовые метки понятны без цвета. Классификация `LEGACY/COMPAT/MIXED/MOSTLY_NATIVE/NATIVE` сохраняет проверенную многометриковую модель; выдуманная скалярная оценка не добавляется. При нулевом знаменателе допуска значение остаётся неизвестным. Допуски для измерений показываются отдельно от трафика привязанных потребителей; вызовы собственного обработчика не считаются повторным внешним допуском.

Профили кодируют схему и версию собственного контракта, ненулевое поколение, явные записи потребителей и идентичность исходников реализации. Отдельно собираемый образ настраивается через `KOLVRT_ROUTING_PROFILE` и независимо доверенную `KOLVRT_ROUTING_DIGEST`. Сборка и EL0 отклоняют ошибки целостности и идентичности, неподдерживаемые модули и версии. Контрольная сумма не является подписью или полномочием оператора; подлинность сборки и загрузки не реализована. Точные контрольные суммы исполняемых файлов отделены от семантических версий и идентичности исходников.

PROD содержит только выбранные возможностями сборки адаптеры и закреплённый профиль. API перепривязки, эксперименты с маршрутами и счётчики DEV отсутствуют. Сборки для проверки явно добавляют тесты соответствия и ограниченную отчётность; облегчённый образ исключает эти тесты и код A/B. Без фиксации событий сборка ядра исключает сбор пользовательских отчётов и связанное с ними хранилище. Проверки корректности, полномочия, границы, защита страниц и время жизни сохраняются. Динамическая выгрузка модуля не заявлена; ненужный код удаляется при проверенной пересборке.

## Измерения и проверки

[Результаты маршрутизации](../../../../research/results/routing-phase2.json) сохраняют контрольные суммы образов пользователя и ядра, байты и суммы профилей, фактические события, эталон ядра, помеченный прогрев и выборки измерений. Шесть конфигураций проверки охватывают DEV/full, PROD/full, PROD/v1, PROD/v2, PROD/bug и PROD/native. Отдельная загрузка облегчённого PROD/v1 исключает диагностические средства. Три проверки обнаруживают повреждённый профиль, локализованный отказ адаптера и повреждённый учёт. [Результаты ядра](../../../../research/results/kernel-phase2.json) сохраняют неизменную матрицу из 53 тестов DEV/PROD и прежние одиннадцать проверок отказов. [Инвентаризация unsafe-кода](../../../../research/results/kernel-phase2-unsafe-audit.json) — перечень, а не доказательство безопасности.

Каждое измерение использует одни зафиксированные собственные данные и одинаковый непустой полезный результат для всех маршрутов. Сохранены шестнадцать выборок прогрева и по 128 измерений для каждого маршрута. Разные потребители чередуют прямой и обратный порядок маршрутов. Граница вызова часов через SVC одинакова; исходная задержка включает переходы привилегий и вытеснение. `black_box` симметрично применяется к входным данным, чтобы фиксированный тестовый образ не исчез при компиляции. Копирования и преобразования на границах исходников учитывают выполненную логическую работу преобразования, а не физические инструкции копирования памяти. На этих ограниченных путях нет выделения памяти или блокировок. Вытеснения таймером записываются для каждого запуска; отдельно измерить загрузку CPU и предельную пропускную способность нельзя.

Эти наблюдения описываются медианой nearest-rank, p95/p99, средним и выборочной дисперсией. Число выборок прогрева фиксировано, но это не доказывает стабилизации; восемь параллельных тестовых задач не являются независимыми испытаниями оборудования. Достоверность хвостов распределения и утверждение о самом быстром пути остаются неустановленными. Более быстрая медиана адаптера совместимости сохранена для исследования собственного пути без искусственных штрафов. Наблюдения эмулятора не устанавливают пропускную способность оборудования, защиту от побочных каналов или продвижение в режиме жёсткого реального времени.

Сборки только с собственным кодом выполняют тот же набор проверок фундамента. Отдельная проверка сокращённой рабочей области собирает систему без пакетов исходников маршрутизации и адаптеров. Замыкание зависимостей Cargo проверяется для всех возможностей собственного ядра; проверки исходников запрещают известные импорты совместимости, старые типы входных данных и условные ветви. Тестовые примеры проверяют эти запреты, границы неверного ELF, отсутствующие, повторные и чужие отчёты, изменение каждого байта профиля, отказ поставщика и отсутствие переключения в PROD. Сгенерированный код и произвольные идентификаторы будущих дополнений всё ещё требуют проверки.

[Доказательства физического удаления исходников](../../../../research/results/native-compat-removal.json) подтверждают, что после удаления пакетов `routing`, `window-compat` и `routing-demo` осталось 35 одинаковых файлов собственного ядра, `kernel-core` и проверочного стенда; изменились только состав зависимостей рабочей области и инструментов, а также lock-файл. В каждом профиле проходят те же 53 теста и одиннадцать проверок на хосте. [Исследование производительности #15](https://github.com/lifeFedorovAlexey/KOLVRT/issues/15) отслеживает восемь наблюдений с меньшей медианой совместимости в сохранённом запуске DEV; неопределённость и следующие проверки приведены в [записи исследования](../../../../research/results/routing-performance-investigation.json). Это не доказывает, что путь быстрее на оборудовании.

## Сохранённая groundwork и следующие кандидаты

Сохранена чистая модель маршрута, семантических имён, схемы/версии/контрольной суммы профиля, неизменяемой конфигурации, правил зависимостей, определений статусов и собственного `Span/Reduction`. Сохранены возможные для среды исполнения `Consumer/Transaction`, диспетчеризация и преобразование адаптеров. Теперь граница обработчика вызывает реальное собственное полномочие из EL0; локальные поставщики остаются тестовыми примерами соответствия. Полезная основа сохранена. Прежнее ограничение «нет доступа с нескольких CPU» заменено исключительным владением каждым потребителем при параллельном исполнении разных потребителей. Прежние одностраничный образ и одиночная загрузочная сессия заменены ограниченными удерживаемыми полезными нагрузками и допуском через CAS.

Переход из собственного кода к перехватчику совместимости не подключён. Среда маршрутизации подключена вне собственного ядра. IPC, дескрипторы и полномочия, отмена, службы, домены безопасности, произвольные загрузчики, перенос общего состояния между доменами, подписи и динамическая выгрузка остаются будущей работой. Кандидаты Phase 3: собственный сценарий IPC и полномочий, затем конкретный потребитель службы; для устройств, DMA и эмуляции Linux нужны отдельные контракты и свидетельства. Демонстрация не устанавливает глобальную политику безопасности для промышленной системы.

Более поздний [планировщик Phase 3.0](scheduler.md) разделяет среду выполнения, архитектурный контекст и загрузочную проверку, добавляя проверяемые поколения и разрешения на доступ к хранилищу для каждого CPU. Привязка адаптера и семантика собственных наблюдений не меняются. [Регрессионные результаты](../../../../research/results/routing-phase3-regression.json) относятся к текущим исходникам планировщика; первоначальные измерения Phase 2 выше остаются историческими. Фундамент собственного ядра теперь также проверяет повторное использование очереди без перезагрузки.

## Phase 3.1 lifecycle regression

Необязательный образ теперь использует [собственный жизненный цикл процессов](processes.md) для создания с владением, явного запуска, точной фиксации завершения и освобождения после безопасной остановки. Поколения процессов отделены от поколений диспетчеризации; поколения адаптеров и профилей остаются закрытыми в EL0. [Текущая регрессия](../../../../research/results/routing-phase31-regression.json) проверяет прежнее поведение выбора маршрута, профиля и изоляции. Выбор маршрута и старое состояние не входят в реестр процессов; прежние записи сохраняют точные исторические исходники.
