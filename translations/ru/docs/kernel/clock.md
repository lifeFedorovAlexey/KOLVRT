# Наблюдения native clock

Document status: CURRENT
Evidence scope: существующий регистровый контракт CLOCK только для чтения и его снимок в SDK; без приёмки исключительного процессорного времени, физического оборудования или производительности.
Current reference: [Пилот паспорта clock](../research/clock-passport.md); [решение о маршрутизации](../architecture-decisions/0015-el0-versioned-routing.md)

<a name="kolvrt-clock-query"></a>

## Запрос clock

Существующий `svc #0x53` читает архитектурный счётчик и накопленные наблюдения исполняющегося процесса. Процесс выбирает принадлежащий планировщику контекст; вызывающий не передаёт селектор процесса. CLOCK не требует grant устройства или IPC и не выдаёт полномочий. SDK `native::clock_snapshot()` именует существующие выходы; `native::clock()` сохраняет результат `(ticks, frequency)`. Ни один API не создаёт новую операцию ядра или путь инструментации.

<a name="kolvrt-clock-query-api"></a>

## Регистровый контракт

| Регистр | Значение                                                                                                 |
| ------- | -------------------------------------------------------------------------------------------------------- |
| x0      | Метка архитектурного счётчика, считанная внутри CLOCK.                                                   |
| x1      | Частота счётчика в тиках в секунду.                                                                      |
| x2      | Накопленные тики окон исполнения текущего процесса, учитываемые на границах синхронных исключений и IRQ. |
| x3      | Накопленные тики вокруг завершённых тел native-обработчика `READ_WINDOW`.                                |

SDK объявляет x4 изменяемым регистром, но не предоставляет его значение. Условное значение при `ipc-benchmark` не входит в этот контракт наблюдения. Счётчики содержат беззнаковые 64-битные значения; потребители проверяют ненулевую неизменную частоту и вычисляют разности с проверкой арифметики. Эти наблюдения внутренние и не заморожены; они не обещают стабильный внешний ABI.

## Границы учёта

Учёт при входе в trap обновляет x2 до возврата снимка CLOCK. Следующее окно исполнения начинается после native-обработчика и заканчивается более поздней меткой входа в вектор. Поэтому разность снимков охватывает завершённые окна исполнения между ними, включая части восстановления и сохранения контекста. Она может включать вытеснение QEMU на хосте и не является исключительным процессорным временем EL0. Тело текущего обработчика CLOCK не входит в неё как измеренный сервисный счётчик.

Счётчик x3 обновляется только после завершения обработчика `READ_WINDOW`. Следующий CLOCK видит этот завершённый учёт. Сам CLOCK не увеличивает x3. У клиента, выполняющего между снимками только запросы CLOCK, каждая разность x3 равна нулю; ноль не означает отсутствие стоимости обработчика CLOCK.

Для проверенных снимков A и B отдельно сохраняются `B.ticks-A.ticks`, разность x2 и разность x3. Их остаток с проверкой арифметики — неатрибутированное истекшее время. Отрицательный результат отклоняет наблюдение, а не заменяется нулём. Остаток не разделяет работу ядра, прерывания, задержку планировщика и планирование хоста. Из него не выводятся счётчик обслуживания IRQ или циклы PMU. Одни и те же публичные поля существуют в DEV и PROD; классы измерений остаются раздельными.

## Владение и ограничения

Сбор снимка читает состояние текущего процесса без выделения, отображения, выдачи или удержания пользовательских ресурсов. Существующие проверки поколения и владения планировщика сохраняют силу. Предоставление уже возвращаемых регистров через SDK не ослабляет изоляцию и не добавляет привилегированный тестовый hook. Более широкая политика часов, доступ к таймеру, синхронизация разных часов и аппаратная точность требуют собственных доказательств. [Пилот](../research/clock-passport.md) — внешний клиент ABI, а не замена production-сервиса.
