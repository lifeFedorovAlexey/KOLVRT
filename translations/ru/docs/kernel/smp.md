# Текущая граница CPU

В QEMU настроены два CPU; ядро выполняет только CPU0. CPU1 остаётся выключенным согласно firmware-контракту PSCI. Вызов CPU_ON, успешная вторичная загрузка, multicore test и реализация SMP не заявляются.

## Следующий milestone

Пользователь прямо разрешил завершить предыдущий работающий уровень, если SMP пока нельзя реализовать корректно. [ADR-0010](../architecture-decisions/0010-kernel-foundation.md) принимает эту границу. До включения другого CPU требуется ревью отдельных стеков и векторов CPU, поиска redistributor по affinity, release/acquire-публикации загрузки, маршрутизации IRQ, cache coherence, подтверждений удалённых TLB и retirement frames. Одна инструкция broadcast TLBI не доказывает безопасное освобождение, пока другой CPU использует отображение.

Конкурентные host tests lock проверяют механизм публикации lock; они не проверяют многопроцессорную загрузку AArch64. Scheduler, userspace и compatibility требуют отдельной инструкции пользователя.
