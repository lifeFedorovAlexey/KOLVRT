# План исследований этапа 0.2

Это первоначальный список исследований. Теперь статус задают [ревью нулевого этапа](phase-0-review.md) и [реестр решений](open-questions.md): модель угроз, двоичный интерфейс первого сценария, конечные модели владения и эксперимент размещения завершены в указанной области. Аппаратное выполнение и исследования расширенных подсистем остаются явно ограниченными условиями или отложенными, а не выполненными этим списком.

Этап 1 не начинается автоматически. Задачи упорядочены по зависимостям и требуют проверяемых результатов.

Применять [отбор исследовательских решений](research-method.md) перед началом каждого пункта. Сначала установить собственную нагрузку, критерий её правильности и ограничения платформы. Глубокое историческое воспроизведение, совместимость, маршрутизация и телеметрия становятся непосредственными приоритетами только при устранении конкретной неопределённости, мешающей этому результату; иначе откладывать их. Таблица является планом исследований, а не обязательным перечнем возможностей.

| Приоритет | Работа и основания приёмки                                                                                                                                                   |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0        | Углубить случаи 07, 08 и 30: полные цепочки изменений, интервалы выпусков, изолированное воспроизведение сбоя и исправления, отрицательные контрольные проверки.             |
| P0        | Модель угроз: злонамеренные приложение, адаптер, драйвер, устройство и встроенное ПО; явная доверенная база и области отказа.                                                |
| P0        | Исполняемая модель маршрутизации: конфликты, запрет понижения версии, завершение обращений, поколения и общие дескрипторы.                                                   |
| P0        | Общее владение: согласованность файлов, блокировок, ожиданий и учётных данных; контрпримеры недопустимого разделения семейств.                                               |
| P0        | Контракты платформы: закреплённые спецификации Arm и VirtIO, инварианты и сравнения с Linux.                                                                                 |
| P0        | Манифест среды ядра: Rust, LLVM, компоновщик, QEMU, машина, процессор и ускоритель; пока без реализации ядра.                                                                |
| P1        | Размещение: законченные прототипы внутри процесса и с межпроцессным взаимодействием на основной системе с одинаковой семантикой запросов.                                    |
| P1        | Кандидат собственного двоичного интерфейса: кодирование, дескрипторы, ошибки, отмена и сроки; матрица совместимости и корпус нечёткого тестирования декодера.                |
| P1        | Модель памяти: копирование при записи, аренда DMA, копирование пользовательских данных, квоты закрепления и завершение времени жизни; обоснования границ и ошибочные модели. |
| P1        | Жизненный цикл совместимости с ошибками: манифесты реальных потребителей, записи прекращения поддержки и прототип проверки зависимостей сборки без совместимости.            |
| P1        | Телеметрия: причинное распределение затрат, вложенное процессорное время, потерянные события, недоступные состояния и стоимость наблюдения с диагностикой и без неё.         |
| P1        | Происхождение: закреплённые редакции документации, контрольные суммы, записи получения и неизвестные первые версии.                                                          |
| P1        | Прочитать первичные изменения до включения удаления arm64 set_fs или futex PI CVE-2014-3153 в базу случаев.                                                                  |
| P2        | Расширить охват Linux: время жизни io_uring, перезапуск сигналов, SysV IPC, TCP/netfilter, LSM, сохранность данных и EEVDF/RT.                                               |
| P2        | Найти свидетельство сохранения обходного решения после исчезновения всего поддерживаемого затронутого оборудования; возраст кода сам по себе не является свидетельством.     |
| P2        | Изучить по одному конкретному сбою, исправлению или миграции Starnix, Redox, seL4, Theseus, WSL1 и Asterinas.                                                                |
| P2        | Повторно оценить реальных потребителей устаревших sysctl, time32 и обязательных блокировок до реализации необязательных адаптеров.                                           |

Заранее описывать критерии правильности, порядок выборки и артефакты экспериментов. Собственные пути не обязаны побеждать. Если свидетельства опровергают предположение, пересмотреть решение и законы с записью причины.

До обсуждения этапа 1 принять модель угроз, контракты платформы и безопасности, обоснованные границы состояния, минимальный кандидат собственного двоичного интерфейса и объём первого сквозного среза. Проверки этапа 0.1 не открывают этот переход.
